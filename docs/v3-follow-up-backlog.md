# TW-Overlay v3 후속 기능·UX 개발 백로그

작성일: 2026-08-26
상태: **계획된 구현·자동 검증 완료 — 실계정·실게임·Windows 실기 검증 대기**

이 문서는 사용자가 메모장에 정리한 16개 과제와 2026-08-26에 추가로 확정한 경험치 HUD·어벤던로드 HUD 정책을 실제 개발 단위로 정리한 내부 계획서다. 여기에 적힌 항목은 구현과 검증이 끝나기 전까지 완료로 표시하지 않는다.

## 1. 공통 구현 원칙

- 기존 동작과 저장 데이터를 먼저 재현 테스트로 고정한 뒤 필요한 부분만 수정한다.
- 설정의 기존 명시값은 보존하고, 새 기본값은 키가 없는 사용자에게만 적용한다.
- 표시 상태, 추적 상태, 데이터 갱신 상태처럼 의미가 다른 상태를 하나의 boolean으로 합치지 않는다.
- 클라우드 상태 표시는 기존 `cloudSyncManager`와 `google-sync-status-changed` 결과를 읽기 전용으로 재사용한다. 창마다 별도 동기화 로직을 만들지 않는다.
- 문서 UI 개선은 콘텐츠 문서와 `docs/guide/index.html` 뷰어를 분리해 검증하며, 문서 변경 때문에 앱 기능을 바꾸지 않는다.
- 각 구현 단위는 자동 재현 테스트를 먼저 추가하고 `npm run typecheck`, `npm test`, `git diff --check`를 통과한 별도 커밋으로 남긴다.

## 2. 권장 진행 순서

1. 사용자에게 이미 혼란을 준 HUD 동작(FUP-17, FUP-18)을 먼저 재현하고 수정한다.
2. 클라우드 상태·인증 UX(FUP-03~FUP-10)를 하나의 상태 모델 위에 구현한다.
3. 일지·알림 기능(FUP-01, FUP-02)을 실제 로그 fixture와 함께 구현한다.
4. 문서 누락 감사와 사용자 가이드 개편(FUP-11~FUP-14)을 진행한다.
5. 버그 제보·계산기·ETA 화면(FUP-15, FUP-16)은 화면별로 분리해 개선한다.

## 3. 게임 데이터·알림

### FUP-01. 금화 주머니를 일일 SEED 획득으로 누적

**상태: 구현 및 자동 검증 완료 (2026-08-26, `7461006`)**

**사용자 의도**

- 금화 주머니 1개를 500,000 SEED로 환산한다.
- 습득할 때마다 새 일지 행을 만들지 않고 날짜별 단일 행의 금액을 누적한다.

**현재 코드 기준**

- `itemAcquisition.ts`는 자신의 금화 주머니 획득과 타인의 획득을 구분할 수 있다.
- 일반 SEED 획득은 `SEED_GAINED` → `activity_logs.type='calc'` 경로로 기록된다.
- 마정석에는 날짜별 UPSERT가 있으나 금화 주머니 환산 SEED 전용 일일 UPSERT는 없다.

**구현 계획**

1. 자신의 금화 주머니 획득 이벤트만 `count × 500,000`으로 환산한다. 타인 공지와 모호한 문장은 제외한다.
2. 채팅 시각은 고유하지 않으므로 이벤트 ID로 사용하지 않는다. 실시간 감지는 로그 tail의 새 줄을 엘소와 같은 방식으로 누적하고, 종료 응답 유실은 별도 operation ID로 정확히 한 번 복구한다.
3. 같은 날짜에는 금액과 마지막 감지 시각만 갱신하고, 날짜가 바뀌면 새 행을 만든다.
4. 과거 로그 재탐색은 파일의 날짜별 전체 합계와 로컬 DB를 비교해 큰 값을 유지한다. 따라서 실시간 반영 뒤 같은 로그를 다시 읽어도 중복 증가하지 않고, 로컬 DB의 더 큰 값도 잃지 않는다.
5. 기존 득템 키워드 기록은 보존하되 월간 수익에서 동일 가치를 두 번 더하지 않는지 확인한다.

**완료 조건**

- 단일·복수·쉼표 수량, 펫 습득, 타인 공지, 동일 시각 복수 획득, 동일 로그 재생, recovery operation 재생 fixture를 통과했다.
- 실시간 두 건이 날짜별 단일 행 1,000,000 SEED로 합쳐지고, 과거 로그 합계가 DB보다 작으면 DB를 보존하며 크면 큰 값으로 보정되는 것을 검증했다.
- 주간 로그 워커 통합 테스트에서 같은 초의 1개와 80개가 단일 행 40,500,000 SEED로 반영되고 재실행 시 추가되지 않는 것을 검증했다.

### FUP-02. 심연의 보물창고 완료 알림 추가

**상태: 구현 및 자동 검증 완료 (2026-08-26, `7fb26a8`)**

**확정된 사용자 의도**

- 기존 `심연의 보물창고 입장 횟수` 기반 숙제 자동 반영은 이미 동작하므로 변경하지 않는다.
- 사용자가 키를 누른 채 다른 화면을 보다가 종료 시점을 놓치지 않도록 완료 알림만 추가한다.
- 완료 판정 원문은 `3분 후 심연의 보물창고 밖으로 자동 이동합니다.`이다.
- 감지 시 알림음을 재생하고 game-overlay에 콘텐츠 종료 안내를 표시한다. 숙제 횟수를 한 번 더 올리거나 캐릭터 선택 정책을 바꾸지 않는다.

**구현 계획**

1. 정확한 완료 문구를 별도 파서 이벤트로 고정한다.
2. 실시간 `chatLogProcessor`에서만 기존 콘텐츠 완료 알림 설정과 알림음을 재사용해 소리와 game-overlay 안내를 보낸다. 과거 로그 워커에는 알림 리스너를 등록하지 않아 재탐색 중에는 알림을 재생하지 않는다.
3. 정확한 실제 로그 문구가 새 이벤트를 한 번 발생시키고, game-overlay 공통 완료 카드에 제목·이동안내·아이콘이 표시되는 것을 검증했다.
4. 새 완료 이벤트가 기존 `ABYSS_TREASURE_ENTRY` 숙제 카운트 경로에 연결되지 않았음을 회귀 검사로 고정했다.

## 4. 클라우드 상태·인증 UX

### FUP-03. 사이드바·독에 동기화 상태 표시

**상태: 구현 및 자동 검증 완료 (2026-08-26~27, `e8785f3`, `c1a6973`)**

- 공통 표시 모듈이 메인 프로세스의 상세 파일 상태를 사용자용 5단계 `정상`, `변경 확인 중`, `업로드 중`, `다운로드 중`, `오류`로 변환한다.
- 사이드바와 독에는 상태 아이콘만 표시한다: 정상은 초록색 점, 확인 중은 회전 확인 아이콘과 황색, 업로드 중은 청색 업로드 아이콘, 다운로드 중은 보라색 다운로드 아이콘, 오류는 적색 오류 아이콘이다.
- Google 계정이 연결되지 않았거나 연결 해제되면 아이콘을 완전히 숨긴다. 연결된 상태에서 자동 동기화를 끈 경우에는 초록 점을 유지하되 툴팁에 자동 동기화가 꺼졌음을 명시한다.
- 아이콘의 커스텀 툴팁으로 짧은 상태 설명을 제공하고, 클릭하면 설정의 Google Drive 카드로 이동한다. 게임 포커스를 빼앗는 팝업은 사용하지 않는다.
- 숨겨진 독 renderer를 재사용하는 현재 정책을 유지하며, 최초 상태 조회와 `google-sync-status-changed` 수신으로 즉시 갱신한다. 업로드·자동 pull 실패 횟수가 갱신된 직후에도 상태를 다시 방송해 오류 표시가 다음 재시도까지 늦어지지 않게 했다.
- 공통 5단계 매핑, 미연결·로그아웃 숨김, 독 상태별 아이콘·툴팁·설정 이동을 자동 검사로 고정했다. 실사용에서 발견된 독 CSS 우선순위 문제는 `hidden`의 실제 계산된 `display:none`과 정상 점의 실제 픽셀 크기를 검사하도록 보강해 빈 슬롯 잔존과 정상 점 미표시를 함께 수정했다.

### FUP-04. 숙제 체크리스트에 동기화 상태 표시

**상태: 구현 및 자동 검증 완료 (2026-08-26, `e8785f3`)**

- 체크리스트 상단에 같은 5단계 상태 아이콘을 표시하되, 파일별 업로드 오류는 `숙제` 파일 상태만 반영한다. 설정 파일만 실패한 경우 숙제 아이콘을 오류로 오염시키지 않고, 공통 pull 실패는 숙제 수신에도 영향이 있으므로 오류로 표시한다.
- 원격 pull 적용 중에는 입력을 막지 않고 상태만 표시한다.
- 오류 툴팁은 숙제 체크리스트 동기화 오류임을 명시하고, 아이콘 클릭 시 재시도·파일별 상세를 확인할 수 있는 설정의 Google Drive 카드로 이동한다.
- 계정 미연결·로그아웃 시 완전히 숨기며, 원격 적용의 기존 origin guard와 dirty/echo upload 정책은 변경하지 않았다.
- 실제 Electron 렌더러에서 미연결 숨김, 정상 초록 점, 확인·업로드·다운로드·숙제 오류 전환, 설정 이동, 로그아웃 후 숨김을 자동 검증했다.

### FUP-05. 설정 화면에서 동기화 상태를 항상 확인 가능하게 표시

**상태: 구현 및 자동 검증 완료 (2026-08-27, `a3f2dce`)**

- 기존 Google 카드와 파일별 상세 상태 렌더러를 재사용한다. 로그인 전에도 카드를 숨기지 않고 `연동 안 됨`과 로그인 동작을 표시한다.
- 로그인 후에는 마지막 성공 시각, 파일별 revision/dirty/retry, 부분 복원 결과를 값 노출 없이 표시한다. 설정 저장 상태와 Drive 작업은 별도 영역에서 `저장 중`, `불러오는 중`, `변경 확인 중`으로 구분한다.
- 인증 만료는 사용자가 누른 연결 해제와 분리해 `다시 로그인 필요`로 표시한다. 제목·설명·버튼·상태 배지가 즉시 바뀌며, 다시 로그인하면 보존된 대기 변경을 이어서 처리한다고 안내한다.
- 실제 Electron 렌더러에서 일반 미연결·연결·인증 만료 UI와 파일별 상세 상태를 검증했다.

### FUP-06. 다른 Google 계정으로 잘못 로그인한 경우

**상태: 이번 개발 범위에서 제외**

- 새 PC에서는 비교할 기존 계정 정보가 없고, 사용자가 의도적으로 다른 계정을 선택한 것인지 앱이 신뢰성 있게 판정할 수 없다.
- Google 계정 선택 자체는 Google 로그인 화면의 책임으로 두고, 앱에서 계정 불일치 차단이나 전환 확인 절차를 추가하지 않는다.
- 기존 보안 원칙인 OAuth 토큰 비노출과 로그아웃 시 토큰 삭제는 그대로 유지한다.

### FUP-07. 3방향 병합 사용자 설명 추가

**상태: 사용자 가이드 반영 및 자동 검증 완료 (2026-08-27, `d56287b`)**

개발 용어만 나열하지 않고 `마지막으로 두 PC가 같았던 상태`를 기준으로 설명한다.

| 상황 | 결과 |
|---|---|
| 이 PC에서만 변경 | 이 PC 변경 사용 |
| 다른 PC에서만 변경 | 다른 PC 변경 수신 |
| 양쪽이 같은 값으로 변경 | 그 값 사용 |
| 같은 숙제의 같은 필드를 서로 다르게 변경 | 실제 플레이를 감지한 로컬 operation을 결정적 순서로 재생해 수렴 |

사용자 가이드에는 서로 다른 캐릭터 변경 보존, 같은 캐릭터·숙제의 완료·해제·횟수 충돌, 응답이 늦을 때 변경 기록 보존, 원격 pending의 캐릭터 선택 팝업, 미완료 후보 한 명 자동 귀속과 리셋 경계 만료를 실제 사용 예시로 추가했다. 필수 문구는 정적 회귀 검사로 고정했다.

### FUP-08. 토큰 만료와 재로그인 유도

**상태: 구현 및 자동 검증 완료, 실계정 권한 철회 실기 대기 (2026-08-27, `a3f2dce`)**

- 앱 시작과 게임 시작의 기존 즉시 pull 경로에서 유효 access token을 사용하고, 만료됐으면 먼저 refresh token으로 조용히 갱신한다. 만료된 access token만 남았거나 갱신이 400/401로 거부될 때만 인증을 무효화한다. 일시적인 네트워크 실패는 일반 재시도 오류로 유지한다.
- 인증 무효화는 사용자의 `연결 해제`와 달리 `googleSyncEnabled`, 설정 dirty key, 숙제 outbox, 종료 recovery marker와 로컬 계정 이메일을 보존한다. 재로그인 성공 경로는 기존처럼 scheduler를 시작하고 즉시 pull·reconciliation을 수행한다.
- 게임 시작 중 설정 창이나 모달을 강제로 열지 않는다. 사이드바·독·숙제 체크리스트에는 숨기지 않은 오류 아이콘을 표시하고, 메인 사이드바에는 `동기화 설정 열기`가 있는 30초 비차단 알림을 한 번 표시한다.
- 설정 창이 이미 열려 있으면 Google 카드가 `다시 로그인 필요`와 `다시 로그인` 버튼으로 즉시 전환된다.
- 인증 만료 뒤 동기화 선택과 dirty/outbox 보존, 공통 오류 표시, 설정·독·숙제 renderer 전환을 자동 검증했다. 실제 Google 계정에서 권한을 철회한 뒤 앱 시작·게임 시작·재로그인으로 복구되는 과정은 실기 체크로 남긴다.

### FUP-09. 동기화 지원 범위·버전 불일치 안내

**상태: 구현 및 자동 검증 완료 (2026-08-27, `53b6f2f`)**

- 설정과 가이드에 일반 설정·숙제 체크리스트만 동기화하며 모험일지 DB, 채팅 로그 원본, 알림 이력, 민감·PC 종속 값은 이 PC에만 보관한다고 명시했다.
- 원격 `schemaVersion`, 파일 종류 또는 알 수 없는 데이터 필드가 현재 앱과 맞지 않으면 손상과 구분한 파일별 `incompatible` 상태와 `현재 버전에서 동기화할 수 없음`을 표시하고, 앱 업데이트 또는 다른 PC 버전 확인을 안내한다. generation 불일치는 기존 파일별 `generation-mismatch` 상태로 분리한다.
- 호환되지 않는 파일은 적용하지 않아 기존 로컬 값을 유지하고, 정상인 다른 파일의 확인·복원은 계속한다. 부분 복원 결과와 `incompatible` 상태는 재시작 뒤에도 보존한다.
- schema·파일 종류·알 수 없는 필드·일반 checksum 손상 분류, 지원하지 않는 설정과 정상 숙제의 실제 부분 복원, 내구 상태 재로드, 설정 화면 결과 문구와 제외 범위를 자동 검증했다.

## 7. 확정 HUD 정책

### FUP-17. 경험치 HUD 표시와 세션 상태 분리

**상태: 구현 및 자동 검증 완료 (2026-08-27, `d153149`)**

**확정 정책**

- 게임 실행 시 경험치 HUD를 무조건 표시하지 않는다.
- HUD 표시 여부는 사용자가 마지막으로 선택한 `showXpWidget` 값을 유지한다.
- 해당 키가 없는 신규 사용자의 기본값은 `숨김`이다.
- XP 세션은 기본적으로 `정지` 상태로 시작한다. 사용자가 명시적으로 자동 시작 옵션을 켠 경우에만 자동 시작한다.
- 세션 시작·정지는 HUD 표시·숨김을 자동으로 변경하지 않는다.

**수정 결과**

- 신규 누락 키 기본값을 `showXpWidget=false`, `xpAutoStart=false`로 변경했다. config의 missing-only 병합이 기존 사용자의 명시값은 그대로 보존한다.
- tracker 시작은 `xpAutoStart === true`일 때만 세션을 활성화하며 HUD 표시 설정을 저장하지 않는다.
- 세션 시작·정지는 추적 상태와 상태 payload만 갱신하고 `showXpWidget`을 변경하거나 config를 재방송하지 않는다.
- 게임 오버레이와 상세 창도 설정이 명시적으로 true일 때만 HUD 표시 상태로 초기화한다.
- 별도 Electron 검사에서 신규 기본값, 누락·false·true 자동 시작 해석, 숨김 상태의 세션 시작, 표시 상태의 세션 정지와 renderer 기본값을 실행한다.

**완료 조건**

- 숨겨 둔 HUD가 게임 실행이나 세션 시작 때문에 나타나지 않는다.
- 표시해 둔 HUD가 세션 정지 때문에 사라지지 않는다.
- 신규 사용자는 HUD 숨김·세션 정지로 시작하고, 명시적으로 자동 시작을 선택한 사용자는 그 설정만 적용된다.

### FUP-18. 어벤던로드 HUD 수동 숨김 유지

**상태: 구현 및 자동 검증 완료 (2026-08-27, `0384410`)**

**확정 정책**

- 사용자가 단축키나 UI로 직접 숨기면 현재 게임 세션 동안 계속 숨긴다.
- 마정석 획득·소실, 입장료, 도전 횟수 데이터는 숨긴 동안에도 정상 집계한다.
- 자동 이벤트는 수동으로 숨긴 창을 다시 열지 않는다.
- 사용자가 메뉴·단축키로 직접 열면 즉시 다시 표시하고 수동 숨김 상태를 해제한다.
- 새 게임 세션에서 수동 숨김 억제 상태를 초기화한다.

**수정 결과**

- tracker에 저장하지 않는 게임 세션 전용 `수동 숨김 억제`를 추가해 활동·집계 상태와 화면 표시 의도를 분리했다.
- 단축키, 강제 표시/숨김 IPC와 마정석 계산기의 숨기기 버튼은 같은 tracker 상태를 사용한다.
- 억제 중에도 마정석 획득·소실, 입장료, 지역 횟수와 수익을 갱신하고 최신 payload를 보내되 `isActive`를 올리지 않는다.
- 사용자가 다시 표시하면 즉시 누적값을 보여주고 자동 숨김 타이머를 다시 시작한다.
- 자동 숨김은 억제를 만들지 않으므로 다음 활동에서 다시 나타나는 기존 동작을 유지한다.
- 게임 최소화·복원에는 억제를 유지하고, 실제 게임 프로세스가 끝난 뒤 새 세션을 찾았을 때만 억제를 해제한다. 수동 통계 초기화도 억제를 해제한다.
- 별도 Electron 검사에서 네 종류 활동의 숨김 유지·집계, 명시적 표시, 새 게임 세션, 0분 자동 숨김 뒤 재표시를 실행한다.

**완료 조건**

- C/S/A 단축키로 숨긴 뒤 마정석 획득·소실, 입장료, 도전 횟수 이벤트를 모두 보내도 HUD가 다시 나타나지 않는다.
- 같은 동안 수익과 지역별 통계는 누락되지 않는다.
- 명시적 다시 열기와 다음 게임 세션에서는 정상 표시가 가능하다.
- 자동 숨김 후 다음 활동에서 나타나는 기존 동작은 수동 숨김과 구분해 보존한다.

## 8. 완료 표시 기준

각 항목은 다음 네 조건을 모두 만족해야 `완료`로 바꾼다.

1. 현재 동작 또는 결함을 재현하는 테스트가 있다.
2. 확정 사용자 정책과 코드 동작이 일치한다.
3. 관련 renderer/main/DB 또는 문서 검증과 전체 자동 게이트를 통과한다.
4. 실기 확인이 필요한 항목은 실제 Windows·게임·Google 계정 검증 결과가 별도로 기록되어 있다.

## 9. 2026-08-27 최종 역감사

- FUP-01~05와 FUP-07~18은 구현 및 항목별 자동 검증을 완료했다.
- FUP-06은 새 PC에서 사용자의 계정 선택 의도를 신뢰성 있게 판별할 수 없어 사용자 결정대로 개발 범위에서 제외했다.
