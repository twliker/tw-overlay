# TW-Overlay v3 후속 기능·UX 개발 백로그

작성일: 2026-08-26
상태: **개발 계획 확정 — 항목별 구현·검증 전**

이 문서는 사용자가 메모장에 정리한 16개 과제와 2026-08-26에 추가로 확정한 경험치 HUD·어벤던로드 HUD 정책을 실제 개발 단위로 정리한 내부 계획서다. 여기에 적힌 항목은 구현과 검증이 끝나기 전까지 완료로 표시하지 않는다.

## 1. 공통 구현 원칙

- 기존 동작과 저장 데이터를 먼저 재현 테스트로 고정한 뒤 필요한 부분만 수정한다.
- 설정의 기존 명시값은 보존하고, 새 기본값은 키가 없는 사용자에게만 적용한다.
- 표시 상태, 추적 상태, 데이터 갱신 상태처럼 의미가 다른 상태를 하나의 boolean으로 합치지 않는다.
- 클라우드 상태 표시는 기존 `cloudSyncManager`와 `google-sync-status-changed` 결과를 읽기 전용으로 재사용한다. 창마다 별도 동기화 로직을 만들지 않는다.
- 문서 UI 개선은 콘텐츠 문서와 `docs/guide/index.html` 뷰어를 분리해 검증하며, 문서 변경 때문에 앱 기능을 바꾸지 않는다.
- 각 구현 단위는 자동 재현 테스트를 먼저 추가하고 `npm run typecheck`, `npm test`, `git diff --check`를 통과한 별도 커밋으로 남긴다.

## 2. 권장 진행 순서

1. 사용자에게 이미 혼란을 준 HUD 동작(FUP-17, FUP-18)을 먼저 재현하고 수정한다.
2. 클라우드 상태·인증 UX(FUP-03~FUP-10)를 하나의 상태 모델 위에 구현한다.
3. 일지·알림 기능(FUP-01, FUP-02)을 실제 로그 fixture와 함께 구현한다.
4. 문서 누락 감사와 사용자 가이드 개편(FUP-11~FUP-14)을 진행한다.
5. 버그 제보·계산기·ETA 화면(FUP-15, FUP-16)은 화면별로 분리해 개선한다.

## 3. 게임 데이터·알림

### FUP-01. 금화 주머니를 일일 SEED 획득으로 누적

**사용자 의도**

- 금화 주머니 1개를 500,000 SEED로 환산한다.
- 습득할 때마다 새 일지 행을 만들지 않고 날짜별 단일 행의 금액을 누적한다.

**현재 코드 기준**

- `itemAcquisition.ts`는 자신의 금화 주머니 획득과 타인의 획득을 구분할 수 있다.
- 일반 SEED 획득은 `SEED_GAINED` → `activity_logs.type='calc'` 경로로 기록된다.
- 마정석에는 날짜별 UPSERT가 있으나 금화 주머니 환산 SEED 전용 일일 UPSERT는 없다.

**구현 계획**

1. 자신의 금화 주머니 획득 이벤트만 `count × 500,000`으로 환산한다. 타인 공지와 모호한 문장은 제외한다.
2. 날짜와 안정된 원천 식별자를 기준으로 멱등 처리한 뒤 `금화 주머니 환산` 전용 일일 SEED 행을 UPSERT한다.
3. 같은 날짜에는 금액과 마지막 감지 시각만 갱신하고, 날짜가 바뀌면 새 행을 만든다.
4. 실시간 처리와 주간 로그 재동기화가 같은 결과를 만들도록 공통 집계 함수를 사용한다.
5. 기존 득템 키워드 기록은 보존하되 월간 수익에서 동일 가치를 두 번 더하지 않는지 확인한다.

**완료 조건**

- 단일·복수·쉼표 수량, 펫 습득, 타인 공지, 동일 로그 재생, 앱 재시작, 날짜 경계 fixture를 통과한다.
- 하루 10회 습득 후 일지에는 환산 SEED 행이 하나만 있고 총액은 5,000,000이어야 한다.

### FUP-02. `심보상 완료` 알림 추가

메모 원문에는 `심보상 완료 알림 추가`로 기록되어 있으나 현재 코드와 문서에는 같은 용어의 이벤트가 없다. 비슷한 이름의 기존 완료 알림에 임의로 연결하지 않는다.

**구현 전 확인 사항**

- 게임에서 사용하는 정확한 콘텐츠명과 완료 조건
- 완료를 확인할 수 있는 실제 채팅 로그 원문
- 캐릭터별/계정별/일일·주간 중 어느 범위에서 한 번만 알릴지
- 데스크톱 알림, HUD, 소리 중 필요한 알림 형태와 기존 알림 설정 재사용 여부

로그 fixture와 사용자 의미가 확정되면 `파서 → 중복 방지 상태 → 알림 설정 → renderer/desktop 알림` 순서로 별도 구현한다.

## 4. 클라우드 상태·인증 UX

### FUP-03. 사이드바·독에 동기화 상태 표시

- 메인 프로세스의 파일별 상태를 `로그아웃`, `정상`, `동기화 중`, `재시도 대기`, `부분 실패`, `재로그인 필요`의 공통 표시 상태로 변환한다.
- 사이드바와 독에는 작은 아이콘·색상·짧은 문구만 표시하고, 클릭하면 설정의 Google 동기화 영역을 연다.
- 게임 포커스를 빼앗는 팝업은 사용하지 않는다.
- 숨겨진 독 renderer를 재사용하는 현재 정책을 유지하고 `google-sync-status-changed` 수신만으로 즉시 갱신한다.

### FUP-04. 숙제 체크리스트에 동기화 상태 표시

- 체크리스트 상단에 설정·숙제 중 `숙제` 파일 상태를 우선 표시한다.
- 원격 pull 적용 중에는 입력을 막지 않고 상태만 표시한다.
- 부분 실패 시 정상 설정 파일과 실패한 숙제 파일을 구분하고, 재시도/상세 확인은 설정 화면으로 연결한다.
- 원격 적용이 새 dirty/echo upload를 만들지 않는 기존 origin guard를 유지한다.

### FUP-05. 설정 화면에서 동기화 상태를 항상 확인 가능하게 표시

- 현재 Google 카드의 파일별 상세 상태 렌더러를 재사용한다.
- 로그인 전에도 카드와 현재 상태를 숨기지 않고 `연결 안 됨`을 명시한다.
- 로그인 후에는 마지막 성공 시각, 파일별 revision/dirty/retry, 부분 복원 결과, 재로그인 필요 여부를 값 노출 없이 표시한다.
- 설정 저장 중 표시와 Google Drive 상태를 혼동하지 않도록 시각적 영역과 용어를 분리한다.

### FUP-06. 다른 Google 계정으로 잘못 로그인한 경우

- 저장된 프로필 이메일과 새 OAuth 프로필 이메일이 다르면 새 토큰을 즉시 확정하거나 자동 pull/upload하지 않는다.
- `기존 계정으로 다시 로그인`, `새 계정으로 전환`, `취소` 선택을 제공한다.
- 새 계정 전환 시 로컬 데이터를 자동 업로드하거나 새 계정의 데이터를 자동 덮어쓰지 않고, 연결 후 백업/복원 선택 화면에서 방향을 다시 확인한다.
- 계정 전환 중 기존 dirty/outbox는 로컬에 보존하며 계정 간에 operation 확인 이력을 공유하지 않는다.
- OAuth 토큰과 이메일은 로그·변경 요약·클라우드 payload에 노출하지 않는다.

### FUP-07. 3방향 병합 사용자 설명 추가

개발 용어만 나열하지 않고 `마지막으로 양쪽이 같았던 상태(base)`, `이 PC(local)`, `Google Drive(remote)`의 세 열로 설명한다.

| 상황 | 결과 |
|---|---|
| 이 PC에서만 변경 | 이 PC 변경 사용 |
| 다른 PC에서만 변경 | 다른 PC 변경 수신 |
| 양쪽이 같은 값으로 변경 | 그 값 사용 |
| 같은 숙제의 같은 필드를 서로 다르게 변경 | 실제 플레이를 감지한 로컬 operation을 결정적 순서로 재생해 수렴 |

완료·해제·횟수·캐릭터 선택 예시와 pending 숙제 팝업 동작도 함께 설명한다.

### FUP-08. 토큰 만료와 재로그인 유도

- 앱 시작과 게임 시작에 자동 동기화가 켜져 있을 때 토큰 유효성을 확인한다.
- 먼저 조용히 access token 갱신을 시도하고, 실패했을 때만 공통 상태를 `재로그인 필요`로 바꾼다.
- 게임 시작 중 설정 창이나 모달을 강제로 열어 포커스를 빼앗지 않는다. 사이드바·독 상태와 비차단 알림에서 `설정 열기` 동작을 제공한다.
- 설정 창이 이미 열려 있으면 Google 카드에 원인과 재로그인 버튼을 즉시 표시한다.
- 인증 실패 중에도 dirty/outbox/recovery는 삭제하지 않고, 재로그인 성공 후 즉시 pull과 reconciliation을 수행한다.

### FUP-09. 동기화 지원 범위·버전 불일치 안내

- 가이드, 로컬 DB/일지, 알림 이력처럼 클라우드 동기화 대상이 아닌 데이터는 설정과 가이드에 명시한다.
- 원격 `schemaVersion`, generation 또는 파일 종류가 현재 앱과 맞지 않으면 `현재 버전에서 동기화할 수 없음`과 필요한 조치를 파일별로 표시한다.
- 한 파일의 불일치 때문에 정상인 다른 파일의 상태 확인·복원을 실패시키지 않는다.
- 알 수 없는 원격 필드는 적용하지 않으며 기존 로컬 설정을 기본값으로 덮지 않는다.

### FUP-10. Google 로그인 가이드와 이미지 추가

- 설정에서 Google 로그인 버튼의 위치, 브라우저 로그인, Google Drive AppData 권한 확인, 연결 계정 확인, 자동 동기화·백업·복원·로그아웃 순서를 설명한다.
- 로그인 화면과 권한 확인 화면 이미지는 계정 이메일·토큰·로컬 경로가 보이지 않는 샘플로 제작한다.
- Drive AppData가 일반 Drive 문서 목록에서 보이지 않는 이유와 앱 데이터 삭제 방법을 함께 안내한다.
- Google 로그인 UI가 실제 릴리즈에서 활성화될 때만 사용자 가이드 탐색에 노출한다.

## 5. 문서·가이드 UI

### FUP-11. 누락 기능과 가이드 전수 감사

- 앱 메뉴/설정 검색 인덱스/관리 창 registry 목록과 `docs/guide/index.html` 탐색 항목을 비교한다.
- 기능은 있는데 문서가 없거나, 삭제된 기능의 문서 링크가 남아 있는 경우를 목록화한다.
- 메뉴에 노출된 기능이 사용자 문서 또는 명시적 제외 목록 중 하나에 반드시 존재하도록 정적 검사를 추가한다.

### FUP-12. 실제 사용자 중심으로 문서 재작성

- 내부 구현 설명보다 `언제 쓰는 기능인지 → 켜는 위치 → 기본 사용법 → 자주 혼동하는 점 → 문제 해결` 순서로 통일한다.
- 기능별 핵심 화면 이미지는 한두 장만 본문에 배치하고 세부 이미지는 갤러리로 분리한다.
- 현재 동작과 다른 홍보성 표현을 제거하고, 자동 동작·저장 위치·동기화 여부·종료 시 동작을 정확히 적는다.

### FUP-13. 가이드 이미지 팝업·확대·슬라이드

- `docs/guide/index.html` 이미지 뷰어를 화면 전체가 아니라 현재 문서 콘텐츠 영역의 중앙에 배치한다.
- 이미지를 클릭하면 원본 비율로 확대/축소하고, 여러 이미지가 있으면 이전·다음 버튼과 키보드 좌우 이동을 제공한다.
- `Esc` 닫기, 배경 클릭 닫기, 포커스 복귀, 이미지 설명, 모바일·좁은 창 overflow를 함께 처리한다.
- 단일 이미지에서는 슬라이드 버튼을 숨기고, 문서 전환 시 이전 갤러리 상태를 폐기한다.

### FUP-14. 모달 너비와 접기/펼치기 UX

- 고정 열 너비를 제거하고 `minmax(0, 1fr)`와 화면 기준 `max-width`로 좁은 창에서도 가로 잘림이 없게 한다.
- 접힌 상태는 최소 높이와 텍스트 clamp를 사용하며 실제 overflow가 있을 때만 `더보기`를 표시한다.
- 펼친 상태에서는 같은 묶음의 설명을 모두 보여주고 마지막에 `접기`를 둔다.
- 한 항목의 높이가 늘어났다는 이유로 같은 행의 다른 항목까지 불필요하게 늘어나지 않도록 grid 정렬을 분리한다.
- `aria-expanded`, 키보드 조작, resize 후 overflow 재판정을 자동 검증한다.

## 6. 화면별 UX 개선

### FUP-15. 버그 제보와 계산기 화면 개편

- 버그 제보와 각 계산기를 한 번에 재작성하지 않고 화면별 사용 흐름·창 크기·입력 오류·결과 가독성을 먼저 기록한다.
- 버그 제보는 무엇을 첨부해야 하는지, 개인정보가 포함될 수 있는 로그의 범위, 외부 폼으로 이동한다는 점을 먼저 안내한다.
- 계산기는 입력 → 계산 결과 → 복사/일지 기록의 주 동선을 우선하고 부가 설명은 접을 수 있게 한다.
- 기존 계산식과 일지 기록 IPC는 그대로 둔 상태에서 renderer만 단계적으로 개선하고 계산 결과 golden test로 회귀를 막는다.

### FUP-16. ETA 랭킹 화면 확대

- 현재 초기 크기 400×600에서 잘리거나 과도하게 스크롤되는 영역을 먼저 측정한다.
- 표·검색·상세 정보가 동시에 읽히는 목표 최소 크기를 정하되 현재 모니터 작업 영역 안으로 제한한다.
- 기존 사용자가 저장한 더 큰 크기는 보존하고 과소 저장 크기만 새 최소값으로 복구한다.
- 800×600급 작업 영역에서는 내부 스크롤로 모든 기능에 접근 가능해야 한다.

## 7. 확정 HUD 정책

### FUP-17. 경험치 HUD 표시와 세션 상태 분리

**확정 정책**

- 게임 실행 시 경험치 HUD를 무조건 표시하지 않는다.
- HUD 표시 여부는 사용자가 마지막으로 선택한 `showXpWidget` 값을 유지한다.
- 해당 키가 없는 신규 사용자의 기본값은 `숨김`이다.
- XP 세션은 기본적으로 `정지` 상태로 시작한다. 사용자가 명시적으로 자동 시작 옵션을 켠 경우에만 자동 시작한다.
- 세션 시작·정지는 HUD 표시·숨김을 자동으로 변경하지 않는다.

**현재 원인**

- 기본 설정이 `showXpWidget: true`, `xpAutoStart: true`다.
- `xpTracker.start()`가 세션 활성 상태를 `showXpWidget`에 즉시 저장한다.
- `startSession()`과 `stopSession()`도 HUD 표시 설정을 각각 true/false로 덮어쓴다.

**구현 계획**

1. 누락 키 기본값만 `showXpWidget=false`, `xpAutoStart=false`로 변경하고 기존 명시값은 보존한다.
2. tracker 초기화에서는 `xpAutoStart`로 추적 상태만 결정하고 `showXpWidget`을 저장하지 않는다.
3. 세션 시작·정지에서 `showXpWidget` 저장과 config broadcast 결합을 제거한다. 세션 상태 갱신 IPC만 보낸다.
4. HUD 표시 토글은 기존 설정/단축키 경로에서만 `showXpWidget`을 변경한다.
5. 앱 시작, 게임 시작, 게임 재시작, 세션 시작/정지, HUD 수동 표시/숨김의 모든 조합을 자동 검사한다.

**완료 조건**

- 숨겨 둔 HUD가 게임 실행이나 세션 시작 때문에 나타나지 않는다.
- 표시해 둔 HUD가 세션 정지 때문에 사라지지 않는다.
- 신규 사용자는 HUD 숨김·세션 정지로 시작하고, 명시적으로 자동 시작을 선택한 사용자는 그 설정만 적용된다.

### FUP-18. 어벤던로드 HUD 수동 숨김 유지

**확정 정책**

- 사용자가 단축키나 UI로 직접 숨기면 현재 게임 세션 동안 계속 숨긴다.
- 마정석 획득·소실, 입장료, 도전 횟수 데이터는 숨긴 동안에도 정상 집계한다.
- 자동 이벤트는 수동으로 숨긴 창을 다시 열지 않는다.
- 사용자가 메뉴·단축키로 직접 열면 즉시 다시 표시하고 수동 숨김 상태를 해제한다.
- 새 게임 세션에서 수동 숨김 억제 상태를 초기화한다.

**현재 원인**

- `AbandonedRoadState.isActive` 하나가 최근 활동과 화면 표시를 동시에 의미한다.
- 수동 숨김 후 `MAGIC_STONE_GAIN`, `MAGIC_STONE_LOSS`, `ABANDONED_FEE`, `ABANDONED_ENTRY`가 `isActive=true`로 바꾸면서 HUD가 다시 나타난다.
- `abandoned-hide-now`도 현재 주석상 다음 입장 로그에서 재표시되는 일시 숨김으로 정의되어 있다.

**구현 계획**

1. tracker 내부에 `수동 숨김 억제`와 `최근 활동/자동 숨김` 상태를 분리한다.
2. 사용자 hide/toggle-off는 억제를 켜고, 명시적 show/toggle-on은 억제를 해제한다.
3. 자동 이벤트는 수익·지역·마정석 데이터와 자동 숨김 타이머를 갱신하되 억제 중에는 표시 상태를 올리지 않는다.
4. 게임 세션 reset에서는 통계와 함께 억제를 초기화한다. 앱 전체 설정인 `abandonedEnabled`와는 별도로 유지한다.
5. renderer는 숨김 중에도 최신 상태 payload를 받아 다시 열었을 때 누적값을 즉시 표시한다.

**완료 조건**

- C/S/A 단축키로 숨긴 뒤 마정석 획득·소실, 입장료, 도전 횟수 이벤트를 모두 보내도 HUD가 다시 나타나지 않는다.
- 같은 동안 수익과 지역별 통계는 누락되지 않는다.
- 명시적 다시 열기와 다음 게임 세션에서는 정상 표시가 가능하다.
- 자동 숨김 후 다음 활동에서 나타나는 기존 동작은 수동 숨김과 구분해 보존한다.

## 8. 완료 표시 기준

각 항목은 다음 네 조건을 모두 만족해야 `완료`로 바꾼다.

1. 현재 동작 또는 결함을 재현하는 테스트가 있다.
2. 확정 사용자 정책과 코드 동작이 일치한다.
3. 관련 renderer/main/DB 또는 문서 검증과 전체 자동 게이트를 통과한다.
4. 실기 확인이 필요한 항목은 실제 Windows·게임·Google 계정 검증 결과가 별도로 기록되어 있다.
