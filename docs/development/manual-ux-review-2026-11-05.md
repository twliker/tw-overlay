# 2026-11-05 실제 화면 UX 검수 후속

## 현재 판정

**로컬 화면 표시 검수와 주요 흐름의 실제 조작을 완료했다.** 제품 빌드의 로컬 화면 41개와 채팅 보조 창 2개의 표시 상태 60개를 확인했다. 프로필·숙제·모험일지·환경설정의 주요 흐름은 실제 Windows 창에서 조작했다. 모든 화면의 모든 버튼을 직접 조작한 결과는 아니다.

화면 검수는 앱이 처음 여는 기본 크기에서 시작한다. 최소 크기는 잘림·겹침·스크롤 경계가 궁금할 때만 추가로 확인한다. 이번 직접 조작의 기본 크기는 프로필 640×520, 숙제 400×1200, 모험일지 1400×920, 환경설정 1100×720이었다.

## 최초 차단과 재개

`computer-use`로 실제 실행 창 목록, 오류 창의 접근성 내용과 검수용 독의 화면/요소를 확인했다. 기존 관리자 개발 앱에는 여러 게임 종료 안내 창과 JavaScript 오류 창이 남아 있었다. 검수용 독에서 프로필 관리 버튼을 누르려 했지만, 기존 창이 덮고 있어 `point (1080, 855) is over electron.exe "Chrome Legacy Window", not target window electron.exe "Dock Launcher"`로 거부됐다. 창을 활성화하고 새 상태를 확인한 뒤 한 번 재시도해도 같은 결과였다. 추가 UI 입력을 중단했다.

처음에는 사용자가 외부에 있어 작업을 중단했고, 이후 사용자가 기존 앱을 종료하고 데스크톱 사용을 허용해 재개했다. 검수용 프로세스만 실행 경로·명령행·PID를 대조한 뒤 종료했다. 기존 Roaming 저장 파일은 입력/수정 대상으로 사용하지 않았다.

## 확인한 결함과 수정

### 1. 개발 콘솔 파이프 오류가 기능 호출자에게 전파됨

실제 오류 창은 `EPIPE: broken pipe, write`와 `console.log → logger.log → diaryDb.addHomeworkLog` 경로를 표시했다. 기존 logger의 개발 콘솔 출력은 예외 처리 바깥에 있었다.

`logger.ts`에서 동기 콘솔 예외와 비동기 stdout error를 격리하고 고장 난 콘솔을 다시 사용하지 않는다. 기존 파일 로그·회전·운영 로그 필터는 유지한다. `test:logger`를 추가해 수정 전 실패를 확인하고, 수정 후 파일 로그와 실제 숙제/음수 SEED 저장이 유지되는지 검사한다. 전체 테스트 명령에도 연결한다.

### 2. 종료 안내를 반복 호출하면 새 창이 계속 생성됨

실제 창 목록에서 다수의 종료 안내가 보였고 코드에서도 호출마다 새 BrowserWindow를 만들었다. 로딩 중 두 번 호출하는 검사로 수정 전 창 2개가 생성됨을 재현했다.

이제 창 하나를 재사용하고 최신 안내·프로필별 숙제 내용을 갱신한다. 최소화된 안내는 복원하고 보고 있던 프로필 탭을 유지한다. 로딩 완료 시 설정을 다시 확인해 비활성화된 안내를 뒤늦게 표시하지 않는다. 기존 alwaysOnTop/권한/Win32 z-order 정책은 바꾸지 않는다. `test:game-exit-reminder`에 로딩 중 재호출·표시 후 재호출·최소화 복원·탭 보존을 추가했다.

### 3. 일반 창 검사의 게임 대역을 기존 앱도 감지할 수 있음

이전 일반 창 검사는 `InphaseNXD-zorder-fixture.exe`를 실행했다. 기존 앱도 게임 프로세스 경로에 `InphaseNXD`가 포함되면 감지하므로, 검사 앱에서 PID를 제한한 것만으로 기존 앱의 관측까지 격리되지 않았다. 앞선 “실행 앱에 영향 없음” 설명은 이 범위에서 부정확했다. 종료 안내 누적에 이 경로가 영향을 줬을 가능성이 있다. 기존 사용자 파일을 열어 변경량을 추정하거나 임의 복구하지 않는다.

일반 `test:profile-windows`는 이제 `TwoverlayProfileFixture.exe`로 빌드하고 검사 프로세스의 탐지 상수만 변경한다. 실제 HWND/PID/Win32/폴링 경로와 소유 PID 제한은 유지한다. 대역 전체 경로에 제품의 기본 게임 탐지 이름이 포함되면 실행 전에 실패한다. 사용자가 실행할 관리자 Z-order 대역의 기본 이름은 유지한다.

또한 `test:profiles:acceptance`가 관리자 Z-order를 `--allow-unelevated`로 대신 실행하던 경로는 사용자 전용 검사 정책에 맞춰 제거했다. 로컬 기능 검증 결과에는 `administratorZOrderStatus=user-verification-required`를 명시한다. 실패를 생략해 관리자 검증을 통과 처리하는 것이 아니라, 사용자 지시에 따라 별도 필수 실기 게이트로 유지하는 것이다.

### 4. 화면 검수에서 확인한 표시 문제

- 사이드바는 메뉴 로딩 전에 클릭 통과 상태가 도착하면 존재하지 않는 버튼에 접근했다. 최신 상태를 보관해 메뉴가 준비된 뒤 적용하고, 렌더러 검수에서 초기 상태가 표시되는지 다시 확인했다.
- 숙제 기본 너비 400px에서 헤더가 433px까지 늘어나 닫기 버튼이 잘렸다. 좁은 헤더 배치와 제목 말줄임으로 제어 버튼을 드러냈다. 숙제 추가·수정 성공 안내를 진하게 표시하고, 실제로 추가한 숙제까지 이동하는 기존 동작을 기본 크기와 작은 높이에서 확인했다.
- 프로필과 숙제 편집의 Windows 드롭다운은 회색 바탕의 대비가 낮았다. 옵션 배경과 글자색을 지정했다. 프로필 서버 메뉴는 실제 창에서 어두운 배경을 재확인했다.
- 작은 모험일지에서는 월 제목과 수치가 단어 중간에서 갈라졌다. 날짜와 합계 배지를 통째로 줄바꿈하고 월 이동 버튼에 접근성 이름을 추가했다. 일별 합계는 지출까지 반영하므로 제목을 **시드 합계**로 표시한다.
- 에타 랭킹의 안내·검색 입력 대비와 오류 안내를 개선했다. 환경설정 데이터 관리 탭은 전환 효과가 끝난 화면과 실제 클릭에서 정상임을 확인해 제품 코드를 바꾸지 않았다.

## 검수 환경과 결과

`scripts/manual-ui-review.ts`는 독립된 임시 appData/userData/채팅 폴더와 배포 기본 숙제·두 프로필을 준비하고 실제 main/preload/IPC/제품 창을 사용한다. 자동 실행·전역 단축키·실제 게임 탐지·원격 감시 시작은 제외한다. `--capture`는 창을 숨긴 상태로 로컬 화면과 조작 결과를 저장하고 외부 HTTP 요청을 차단한다. `--screens=profiles,contents-checker,diary`처럼 범위를 지정해 관련 화면만 다시 확인할 수 있다. `--desktop-tools`는 제품 도구 창을 기본 크기로 열어 Windows에서 직접 조작할 때 쓴다.

| 화면/흐름 | 실제 확인 범위 |
|---|---|
| 프로필 | Windows 창에서 진행 막대와 입장료 대기 요약 확인, 순서 이동, 서버 선택, 설정을 복사해 새 프로필 저장·사용 |
| 숙제 | Windows 창에서 편집·추가, 저장 안내, 해당 줄로 스크롤, 15초 자동 접기와 펼치기 확인 |
| 모험일지 | Windows 창에서 수동 지출 `-11억 8190만 시드` 저장, 월·일·기록 표시, 미배정 조회에서 제외 확인. 통계와 이전 프로필 정리는 화면 표시 확인 |
| 환경설정·공지 | Windows 창에서 데이터 관리 탭 전환과 동기화 안내, 앱 설정 저장, 업데이트 공지 닫기. 다른 설정 탭과 가이드는 화면 표시 확인 |
| 사이드바·독·종료 안내 | 화면 표시, 사이드바 초기 상태, 종료 안내의 프로필 탭을 검수 빌드에서 확인. 독 버튼은 검수 도구의 포인터 대상 확인이 거부해 실제 클릭을 마치지 못함 |
| 계산기·스톱워치·사전·사냥·HUD·알림·채팅·거래·갤러리 | 로컬 화면과 준비된 데이터 상태 표시 확인. 실시간 입력과 외부 응답은 미확인 |
| 제복·검 강화·QTE·오버레이 브라우저 | 로컬 창 표시 확인. 외부 페이지와 실게임 연동은 미확인 |

## 자동 검증과 한계

산출물은 `output/manual-ui-review/`에 있다. 전체 표시 검수는 `captures/summary.json`의 60개 상태·6개 흐름, 환경설정/에타 재검사는 `capture-focused.log`의 9개 상태·2개 흐름, 최종 프로필/숙제/일지 재검사는 `captures-focused/summary.json`의 13개 상태·3개 흐름이다. 모두 미완료 검사 0개였다. 전체 검수에 기록된 외부 글꼴 CSP 경고 5건은 로컬 대체 글꼴로 표시됐으며 보안 정책은 유지했다.

빌드·앱/도구 타입 검사·변경 파일 공백 검사와 `test:profiles-ui`, `test:profile-checklist`, `test:diary-profiles-ui`, `test:diary-calendar`, `test:eta-ranking`이 통과했다. 앞선 오류 보완에는 `test:logger`, `test:game-exit-reminder`, `test:profile-diary`, `test:profile-recording`, `test:window-visibility`, 전용 프로세스명을 사용한 `test:profile-windows -- --with-reminder`의 12개 조합을 실행했다. 최초 실패 로그 `logger-red.log`, `reminder-red.log`를 보존했다. 전체 회귀는 반복하지 않았다.

실게임, 게임에 붙은 독의 메뉴 클릭, 사용자가 수행하는 관리자 Z-order, 실제 Google 계정과 두 PC 왕복, 설치 업데이트는 이번 검수 범위에서 확인하지 않았다. 앞선 런타임 패키지의 해시는 당시 결과다. 이번 변경은 검수 작업 폴더에 있으며 원래 앱이나 사용자 데이터에 적용하지 않았다. 푸시·태그·게시하지 않았다.
