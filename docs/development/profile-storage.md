# 프로필 구현 진행

2026-11-04 후속 Google 재개발은 [Google 검증](./google-sync-verification.md)과 새 전용 경로를 따른다. 이 문서의 Google 중지는 구형 전송 경계이며 로컬 프로필 목표 당시의 기록을 보존한다.

저장 계층, 프로필 선택·관리 화면, 시스템 메뉴/IPC, 게임 세션 제어, 기존 Google 중지 경계 및 모험일지의 공유 연결/프로필별 저장·조회 계층을 작성했다. main의 profileApplication이 부팅 전에 저장소·기존 Google 중지·기록 경계를 준비한다. 다음 일반 실행부터 원본 백업 후 이전/선택 대기를 적용한다. 사용자 폴더의 실제 데이터 이전은 실행하지 않았다.

## 원본과 소유권

- `src/shared/playProfiles.ts`: 프로필/공통/기기 설정의 소유권 목록. 기존 `userServer`는 프로필 설정 한 곳만 원본으로 가진다.
- `src/modules/applicationData.ts`: `app-data.db`의 프로필·설정·숙제·대기 이벤트·변경 이력. 모험일지는 같은 DB에 보존하되 동기화 이력을 생성하지 않는다.
- `src/modules/config.ts`: 선택적으로 설치하는 persistence 경계. 기존 읽기 API는 선택 프로필의 메모리 projection을 제공하고, 새 계층이 연결된 경우 `config.json`에는 기기 설정만 저장한다.
- `src/modules/profileService.ts`: 새 게임 세션의 선택 대기, 반복 감지 멱등성, 프로필 전환 취소/실패 복구, 현재/이전 세션 대기 기록 배정. 새 세션 저장 실패도 마지막 프로필에 자동 기록하지 않는다. 전환 확인 중 게임 상태가 바뀌면 늦은 선택을 취소한다.
- `src/modules/profileGameLifecycle.ts`: 실행/최소화 최초 발견은 한 번 선택하고 최소화 복귀는 같은 세션을 유지한다. `pollingLoop.ts`와 runtime registry 경계를 연결했다. runtime은 profileApplication에서 파서/게임 폴링 전에 등록한다.
- `src/profiles.html`, `renderer/profiles.ts`, `modules/profileIpc.ts`: 실제 preload/관리 IPC 및 시스템 메뉴. 프로필 이름은 자유로운 표시 이름이며 실제 캐릭터 이름을 입력받거나 이름으로 에타를 조회하지 않는다. 필수 서버는 기존 userServer 하나이고, 채팅 실제 닉네임의 기존 에타 조회에 사용한다.
- `src/modules/cloudSyncManager.ts`의 `pauseForPlayProfiles`: 기존 자동·수동·예약 전송과 늦은 응답을 중지하고 인증/dirty/outbox는 보존한다. 실제 부팅에서 프로필 저장소 연결 전 이 Promise를 기다려야 한다. 설정 화면의 중지 안내도 구현했다.
- `src/modules/profileClock.ts`: 앱 내부 인터넷 기준 시계. Windows 시간 설정은 바꾸지 않는다. 시간 확인 실패/기준 만료는 `unverified`로 기록한다.
- `src/modules/diaryAttribution.ts`, `shared/diaryProfiles.ts`: nullable 기록 귀속 및 조회 범위의 공통 계약. 원래 행을 현재 프로필로 추정하지 않는다.
- `src/modules/diaryDb.ts`의 `connectApplicationData`: 기존 연결을 닫고 검증한 저장소를 연결하면 이후 저장/재연결도 동일 app-data.db만 사용한다. 일지 스키마 user_version=9와 프로필 저장소 app_meta schema_version=1은 서로 독립적이다.
- `modules/diaryProfileAccess.ts`, `renderer/diary-profiles.ts`, `renderer/diary/profile-filter.ts`: 일지의 전체/프로필/미배정 조회와 명시적 수동 저장 대상. 달력·일/주 상세·통계·득템·수익·HTML 내보내기에 같은 필터를 전달한다. 프로필 관리와 동일한 상태 알림을 구독하며 별도 프로필 선택 상태를 만들지 않는다.
- 수동 득템/SEED·마정석 수익·보스 설정/사이드바 기록: 입력 시작/저장 클릭 시 대상을 고정하고 전환/늦은 응답으로 재배정하지 않는다. 프로필 모드에서 대상 생략·삭제·미완성 ID는 메인에서도 거부한다. 조회할 수 있는 삭제 프로필은 새 수동 기록 대상에서는 제외한다.
- `modules/profileStartup.ts`: 기존 Google 전송 배출 → 지연 설정 확정 → 기존 DB 닫기 → 이전/공유 연결 → 설정 projection → 선택 대기 순서의 준비 API. 중복 호출은 같은 Promise를 공유하고 인터넷 시간 조회 실패는 로컬 실행을 막지 않는다. main에서 게임 폴링·파서·일반 창 시작 전에 호출한다.
- `modules/profileParserEvents.ts`, `recordEffects.ts`, `profileRecording.ts`: 실제 프로세서/추적기의 프로필 소유 처리를 한 이벤트로 모아 service의 대기/transaction/ACK에 연결한다. 원시 채팅 표시는 그대로 유지한다. main은 profileApplication의 통합 경계를 사용한다.
- `modules/profileBackupRestore.ts`, `backupManager.ts`, `localSnapshot.ts`: 실제 ZIP 백업/복원에 app-data.db를 포함한다. 프로필 DB가 있으면 보존용 diary.db를 새 백업에 중복 포함하지 않는다. 구형 설정/일지의 부분 백업은 잠근 DB의 복사본에서 변환한 뒤 검증 결과를 게시한다.

## 이전과 저장

`ApplicationData.initialize`는 앱의 단일 인스턴스 잠금과 기존 DB 쓰기 중단 후 호출해야 한다. 기존 `diary.db`를 SQLite online backup으로 staging에 복제하고 테이블 건수·금액 합계·무결성 및 원본 변경 여부를 검증한다. 기존 설정/DB는 `backups/before-play-profiles-*`에 보존한다. 완료된 `app-data.db`가 있으면 원본을 재복사하지 않는다. 실패한 staging 파일은 다음 실행의 원본 후보가 아니다.

기존 선택 캐릭터는 `profile-default`를 사용하고 나머지 캐릭터만 별도 ID로 이전한다. 신규 설치는 빈 기본 하나를 만든다. 기본 서버 값을 사용자 선택의 증거로 삼지 않고 실제 `config.json`에 저장된 유효 서버만 승계한다.

숙제/설정 변경과 변경 이력은 같은 DB transaction으로 저장한다. 기기 JSON과 DB를 함께 변경할 때는 복구 journal을 먼저 남기며 DB commit 실패·중단 시 JSON도 이전 내용으로 복구한다. 선택 프로필 전환 전에 대기 중이던 이전 프로필 설정을 먼저 저장한다.

프로필/숙제만 변경하는 저장은 DB transaction 안에서 끝낸다. 대기 이벤트의 일지·숙제·설정·ACK가 함께 rollback할 수 있으며 기기 JSON을 다시 쓰지 않는다. 외부 DB transaction 중 기기 JSON 변경은 허용하지 않는다. 반영 실패 시 config 메모리 projection도 DB에서 갱신해야 한다.

기존 일지 행은 `profile_id=NULL` 및 고유 기록 ID를 갖는다. 신규 기록의 프로필·기기·세션 귀속은 같은 DB 연결의 record context를 사용한다. 다른 연결에서 임의 쓰기를 하면 이 계약을 보장할 수 없으므로 일지 모듈도 동일 연결을 사용하도록 연결해야 한다. 수동/과거 복원 경로는 저장 대상 context를 명시해야 한다.

일지 모듈의 공유 연결 API와 실제 SQLite 검증은 완료했다. 부팅에서는 기존 일지 연결을 닫고 이전을 완료한 뒤 `connectApplicationData(store)`를 호출해야 한다. 일지 연결을 닫으면 저장소도 닫고, 복원 잠금 해제 뒤에는 같은 app-data.db를 다시 연다. 외부 transaction/버퍼 저장 실패 중에는 닫지 않으며 diary.db로 되돌아가지 않는다. 프로필 저장소를 다시 열 때도 schema와 이전 완료 marker를 확인한다.

날짜별 점수·완료 횟수는 `diary_profile_days`에 프로필별로 보관하고 기존 `diaries`는 전체 합산을 유지한다. 기존 통계는 미배정에 한 번만 이전한다. 숙제/보스/마정석 중복 판단, 금화·엘소 합산, 과거 자동 기록 교체도 대상 프로필에 한정한다. 수동 원본 ID로 삭제할 때는 실제 소유 프로필의 점수를 차감한다. 삭제된 프로필의 기록/통계는 보존하고 데이터 보존 기간 정리는 일지와 요약을 함께 정리한다.

금화/엘소 journal v2는 입력 당시 귀속을 저장한다. 복구 중 선택이 바뀌거나 원래 프로필이 삭제돼도 재배정하지 않는다. 소유자가 없는 v1은 미배정으로 복원한다. 복수 기기/세션이 한 날짜 행으로 합쳐지면 해당 provenance만 null로 바꾸고 프로필과 기록 ID는 유지한다. 외부 대기 이벤트 transaction에서는 버퍼/파일 쓰기를 하지 않고 일지·프로필·ACK와 함께 확정/rollback한다. 읽기 API는 전체/지정 프로필/미배정 필터를 지원하며 조회만으로 날짜를 생성하지 않는다. 전체 조회의 득템은 각 원본 프로필의 키워드를 따른다.

과거 worker가 날짜별 금화·엘소·마정석 합계에도 재실행 시 같은 프로필별 source ID를 제공한다. 원본 구간의 귀속으로 다른 프로필/미배정 기록의 복제를 막으며 같은 프로필의 snapshot 재구성은 허용한다. 구형 미배정 일 합계는 원본을 남기고 기준량을 뺀 차액만 기록한다. 상세는 아래의 과거 복원 계약을 따른다.

## 검사

```powershell
npm run typecheck
npm run build
npm run test:profile-storage
npm run test:profile-diary
npm run test:profile-backup
npm run test:profile-recording
npm run test:diary-profiles-ui
npm run test:profiles-ui
npm run test:profile-cloud-pause
```

임시 사용자 폴더와 실제 SQLite/WAL을 사용한다. 기존 2캐릭터 → 2프로필, 원본/이력 보존, 설정·숙제 격리, 기본 프로필 생성/삭제, 동일 이벤트 재시도, 세션별 대기와 rollback, DB commit 실패 후 JSON 복구, 앱 설정 API 연결, 시간 기준/만료·조회 실패를 검사한다. 인터넷 시간 네트워크는 개발 환경에서 한 번 조회 성공을 확인했다. 광범위한 네트워크 환경의 정확도·가용성 검증은 별도다. 프로필 제어 계층은 실제 config API·일지 스키마를 사용해 선택 전 대기, 전환 취소/런타임 실패 복구, 현재 세션만 재생, 이전 세션 명시 배정을 검사한다.

UI 검사는 제품 HTML/preload/IPC/SQLite로 서버 필수, 임의 표시 이름, 설정 복사, 저장만 했을 때 선택 유지, 초안 보존/취소, 저장 실패/재시도, 세션 배정, 마지막 삭제 후 빈 기본, 준비 전 재시도 및 최소 창 크기를 확인한다. Google 검사는 중지 전에 시작한 요청·예약 요청의 배출, 중지 후 자동/수동 호출 차단, 로컬 설정/인증/기존 outbox 보존과 실제 설정 카드 DOM을 확인한다. 두 화면은 캡처 이미지로도 확인했다.

창 관리 변경은 `npm run test:window-visibility`로 확인했다. 프로필 관리 창은 게임 최소화·종료로 닫지 않으며 작성 중인 입력을 보존한다. 사용자가 명시적으로 전체 창 숨김을 실행한 경우에는 함께 숨긴다. 이미 최소화된 게임 감지 시에는 기존 오버레이 숨김을 끝낸 다음 선택창을 열어 바로 닫히지 않게 한다.

일지 검사는 실제 이전/공유 연결·원본 파일 불변, 수익/지출·숙제·마정석·금화·엘소의 분리와 전체 합계, 프로필별 득템 표시, transaction/ACK 실패 재시도, journal 중복 재생·이전 버전 복구·삭제 프로필, 필터별 통계/내보내기와 외래 키/무결성을 확인한다. 기존 마정석 실제 UI/IPC 검사를 함께 실행하며, 과거 worker/재구성 검사는 `check-refactor-regressions.ts` 파일 단위로 실행한다. 전체 npm test를 각 단계에서 실행하지 않는다.

## 통합 상태와 후속 검증

로컬 프로필 기능의 자동 검증은 **완료**했다. `test:profiles:acceptance`의 26개 필수 단계와 소스/패키지 각각 12개 Windows 시작 조합을 통과했고 `test:profiles:proof`로 현재 코드의 결과임을 확인했다. 요구사항별 근거는 [자동 검증 기준](./profile-acceptance-matrix.md)을 따른다. 아래 실게임·권한·설치 검증은 배포 환경 확인으로 구분한다.

일반 부팅, 실시간 기록, 과거 복원, ZIP 복구 중 입력 중지와 실패 이어받기, 주기/종료 저장 및 활동 프리셋 UI/IPC 제거를 연결했다. 아래 앱 수명 계약을 따른다. 실제 사용자 폴더는 검사하지 않았으며 다음 일반 실행부터 원본 백업 뒤 이전한다.

남은 실기는 실제 게임에서 앱→게임/게임→앱·최소화 상태 시작, 서버가 다른 프로필 전환, 대표 콘텐츠와 창 동작 및 설치 업데이트 경로다. 새 Google 동기화는 이번 범위에 포함하지 않는다.

마무리 검증과 발견한 결함의 수정 결과는 [프로필 기능 마무리 검증](./profile-completion-verification.md)에 기록한다. 실제 Windows 게임 대역을 사용하는 검사와 구버전 설치 패키지의 저장 API로 만든 데이터 이전 검사를 추가했으며, 실게임·관리자 권한·실제 설치 프로그램 검증과 구분한다.

### 별도 프로세스 재시작 검증 (2026-11-04)

`test:profile-lifecycle`은 같은 임시 사용자 폴더를 두 독립 Electron 프로세스에서 순서대로 열어 앱 종료·재시작을 확인한다. 이전한 두 프로필의 수/ID, 서로 다른 서버·메모, 커스텀 숙제 횟수/N/A, 계수 계산기 저장 입력, 프로필별 일지 합계와 완료 이벤트 영수증이 유지된다. 다음 실행은 마지막 프로필에 자동 기록하지 않고 선택을 다시 요구한다.

종료 직전 감지한 미배정 지출은 다음 실행에서 프로필을 선택해도 자동 배정하지 않는다. 이전 세션을 명시적으로 배정하면 한 번만 반영하며 재확인으로 중복되지 않는다. 검사 데이터는 임시 폴더에만 생성한다. 이 자동 검사는 실제 게임 플레이와 설치 파일 업데이트 실기를 대신하지 않는다.

## 자동 기록과 실행 상태

과거 복원은 아래의 잠금/대기 경계를 사용한다. 실시간 원본 위치 귀속과 ZIP 교체 중 로그 정지/실패 후 이어받기도 아래 통합 경계로 연결했다.

일지·숙제·XP·버프 등의 소유 처리는 `onProfileEvent`/`onProfileProgress`에 등록한다. 같은 파서 이벤트가 여러 소비자를 가져도 대기 원본은 한 건이며, 아이템 획득과 숙제처럼 원래부터 별도 파서 이벤트인 경우에는 각각 보관한다. 일반 채팅/외치기 표시는 원래 parser에 남긴다. 일반 채팅은 기존 XP 도전과제 시작 명령만 진행 이벤트로 분기한다. 사용자 색상 분류·시스템 채팅 표시를 기록 대기와 함께 멈추지 않는다.

실시간 선택 완료 상태에서는 enqueue와 반영/ACK를 한 번의 outer commit으로 처리한다. 반영 실패는 savepoint만 취소해 원본 대기를 남긴다. config의 `withConfirmedWrites`는 실패한 캐시/지연 저장을 복구하고 다른 프로필에서 자동 재시도하지 않게 한다. 일지·숙제·ACK가 성공한 뒤 `recordEffects`가 알림/진행 상태를 적용한다. 현재 세션의 진행만 재생하며, 이전 세션 수동 배정은 현재 HUD/버프/소리를 바꾸지 않는다. 지난 순간 알림은 다시 울리지 않는다.

`profile_runtime_state`는 프로필별 로컬 실행 상태이며 Google 변경 이력에 넣지 않는다. 전환 전 XP 누적/측정 시간·도전과제, 버프 원래 시작/경고 상태, 어벤던로드 집계/숨김, 발굴지·보급품 및 최근 감지를 저장한다. 비활성 프로필의 측정 시간은 늘리지 않고, 버프/현황판/도전과제의 실제 만료 시각은 유지한다. 새 게임 세션은 이전 현황판과 사용자 숨김 억제를 이어받지 않는다. `checkpoint`는 ZIP 백업/복구 사본 생성에도 호출하며 종료와 1분 주기 저장은 main에 연결했다. 처리 완료 원문은 30일 뒤 해시 영수증으로 줄이고 미배정 원본은 보존한다. 강제 종료 직전 미저장 실행 상태는 마지막 checkpoint 이후 손실될 수 있다.

`check-profile-recording.ts`는 실제 로그와 SQLite로 선택 전 대기·채팅 지속, 프로필별 귀속, 일지/설정/ACK 실패와 한 번 재시도, 늦은 알림 억제, 이전 세션 배정, 진행 상태 재조립/실제 ZIP 백업을 확인한다. 개발 PC에서 100건 연속 XP 처리 약 0.1초를 관찰했으며 배포 환경 전체 성능 보장은 아니다. 관련 기존 검사는 XP 정책·버프·마정석·보조 기능·저장/백업 및 refactor 검사 파일 단위로 선택 실행했다.

## 도구 입력과 전환 보호

스톱워치는 `profileStopwatch.ts`에서 프로필별 메모리 세션을 보존한다. 전환해도 원래 측정은 벽시계 기준으로 계속되고 원래 프로필로 돌아와 종료한다. 앱 종료 시 미종료 측정을 저장하지 않는 기존 계약을 유지하며 실행 상태/Google 변경 이력/프로필 복사에도 넣지 않는다. 선택 대기에는 측정을 거부하고, 진행 또는 입력 처리 중인 소유자의 삭제도 거부한다. 시작 입력 때 DB 도구 값과 프로필/플레이 세션 ID를 고정하고 종료 기록에 같은 귀속을 사용한다. 저장 실패는 진행 상태를 유지해 다시 종료할 수 있다.

관리 창과 HUD는 공통 revision으로 현재 프로필 상태만 반영한다. 전환 시 다른 프로필의 HUD 시계를 숨기고 돌아오면 원래 시작 시각을 사용한다. 기록은 현재/전체/지정/미배정 및 삭제 프로필로 조회하며 늦은 이전 조회는 반영하지 않는다. 제목 편집 중에는 자동 갱신/전환에도 초안을 유지하고 저장 실패 시 Enter 재시도/Escape 취소를 제공한다. 전환 시 편집하던 프로필의 목록을 유지한다. 수정·삭제는 로컬 관리 페이지의 확정 IPC로 원래 행에 적용하며 기존 무응답 쓰기 IPC는 프로필 모드에서 차단한다. 재계산은 저장된 시작 효과를 사용하고 구형 기록만 원래 소유자의 도핑을 읽는다. 삭제된 소유자의 도핑을 확인할 수 없으면 재계산을 거부하고 미배정 기록은 보존한 이전 브라우저 저장소를 사용한다.

`npm run test:profile-stopwatch`는 실제 관리 창/HUD/preload/IPC/공유 DB로 병행 측정·전환·귀속/스냅샷·실패 재시도·삭제 보호, 기존/삭제/미배정 기록, 늦은 조회·제목 초안·DB 실패·실제 포커스와 1000×800/800×600 화면을 확인한다. 기존 모드는 `test:stopwatch`, 직접 영향이 있는 전환/저장/도구 검사는 `test:profile-recording`, `test:profile-storage`, `test:profiles-ui`, `test:profile-tools`로 확인했다. 일반 부팅과 복구 중 중지 경계는 통합했다.

계수 계산기와의 실제 연동 검사도 포함한다. 제품 계산기에서 능력치·장비 수치·강화·코어·계산 프리셋을 변경하고 다른 프로필의 도핑 선택과 분리되는지, 돌아왔을 때 각 입력/마지막 선택이 복원되는지 확인한다. 측정 시작 후 입력을 다시 수정하거나 프로필을 바꾸어도 원래 프로필의 시작 당시 계산값/도핑으로 실제 SQLite 기록이 생성되는 것까지 검증한다.

`profile_tools`는 계수 계산기의 계산 프리셋/마지막 선택/구형 입력, 버프 백과의 프리셋/선택 버프/현재 프리셋을 프로필별로 저장한다. 최초 준비 때 file-origin에 저장된 실제 값을 모든 이전 프로필로 한 번 복사하며 원본은 남긴다. 기존 프로필의 사용자 수정값은 재실행으로 덮어쓰지 않는다. 새 기본값 프로필은 비어 있고, 환경설정 복사 생성은 이 도구 입력도 복사한다. 진행도·일지·실행 타이머는 복사하지 않는다. 이 표는 로컬 전용 실행 상태와 달리 향후 동기화 대상 변경 이력에 포함한다.

각 도구 창은 입력 프로필을 표시하고 열린 페이지에 고정된 token으로만 저장한다. 전환 뒤 늦은 요청도 새 프로필로 재배정하지 않으며 임의 키/외부 페이지/다른 token은 거부한다. 버프 백과의 프리셋 변경은 같은 프로필을 보고 있는 계수 계산기에 즉시 전달한다. 계산기 안의 여러 계산 프리셋은 앱 플레이 프로필과 별개로 유지한다.

`profileToolTransition`은 실제 창의 입력을 commit 전에 저장하고 확인 중 입력을 잠근다. 버프 프리셋 생성/실제 수정 또는 계산기 이름 입력 중에는 작성 내용을 보존하고 해당 창을 보여준 뒤 완료/취소를 안내한다. 저장 실패는 선택과 입력을 보존하며 재시도 가능하다. 변경 없이 버프 편집을 열기만 한 경우와 같은 프로필을 재확인한 경우에는 불필요하게 막지 않는다. 성공/취소/rollback 모두 잠금을 해제하고 성공 뒤 새 소유자의 값으로 다시 연다. 삭제된 소유자에게 뒤늦게 재저장하지 않는다. 설정 화면은 아래의 별도 초안 경계를 따른다.

`check-profile-tools.ts`에서 제품 HTML/preload/IPC/SQLite, 실제 저장값 이전·재실행 방지, 프로필 분리/복사/삭제, 고정 귀속·잘못된 요청, 편집과 DB 실패 후 재시도, 이름 변경 및 800×600 화면을 검사한다. 기존 모드 버프/계산기 연동은 `test:buffs`로 유지한다. 신규 프로필 DB가 포함된 ZIP은 DB 도구 값이 원본이며 공용 renderer 키로 덮지 않는다. 구형 renderer 저장소만 있는 검증된 백업은 현재 모든 프로필로 변환하고 일지·프로필 설정은 유지한다. 실제 ZIP 교체·실패 rollback은 `test:profile-backup`에서 검사한다.

## 설정 초안의 프로필 경계

사냥 경험치 계산기·경험치 HUD·버프 타이머·보스 설정·커스텀 알림도 `renderer/profile-settings-page.ts`를 통해 같은 전환 경계를 사용한다. `profileSettingsAccess`는 해당 로컬 페이지의 ID 생략/다른 ID를 거부하며 첫 비동기 작업 전에 저장 대상과 제출 값을 고정한다. 화면에는 프로필 이름/서버와 실제 공통 적용 항목을 표시한다. 같은 소유자의 수신이 편집/저장 중 입력을 덮지 않고, 성공 ACK는 제출한 필드만 승인하며 다른 초안과 이전 소유자의 늦은 ACK를 승인하지 않는다. 검색/조회와 단순 스크롤은 초안으로 취급하지 않는다.

화면 전체 저장도 실제 변경한 필드만 제출한다. 다른 창이 바꾼 공통 음량 등을 오래된 화면 값으로 되돌리지 않는다. 저장 중인 필드는 원래 값으로 되돌린 후속 입력도 큐에 남긴다. 해당 공통 값 보존과 빠른 되돌리기 입력도 실제 IPC/DB 검사에 포함한다.

프로필 전환은 공통 `profileSettingsTransition`의 저장/버리기/취소를 사용하며 뒤이은 전환 실패는 원래 폼과 선택을 유지한다. 새 항목은 실패 시 입력을 남기되 취소하면 목록에서 사라지고 재시도는 같은 ID를 사용한다. 저장 중 추가 입력이 있으면 폼을 닫지 않는다. 사냥터/도핑 저장 실패는 임시 목록 변경을 되돌리고 커스텀 알림은 확정 후 목록에 반영한다. 입력 검증 실패는 전환하지 않고 안내한다. 저장 중에는 전환을 거부하고 시작 중인 테스트 버프도 설정 성공 후 실행한다. 알림음 비동기 목록은 세대를 확인하며 초기 수신이 끝나기 전 입력하지 못하게 한다. 경험치 HUD는 기존에 저장된 임의의 유효 휴식 시간도 선택지로 보존한다.

`test:profile-settings-pages`는 임시 사용자 폴더에서 실제 5개 HTML/preload/IPC/공유 DB로 각 설정의 분리/복원·필수 값, 저장/버리기/취소·후속 실패, 부분 ACK·지연 저장/다음 초안, 실패 후 취소/중복 없는 재시도, 이전 소유자/ACK/알림음, 공통 0% 음량과 이름 변경·800×600 화면을 검사한다. `test:settings-pages`는 기존 5개 화면/음량 경계만 선택 실행한다. main 설정의 `test:profile-settings`, 보스 일지의 `test:diary-profiles-ui`와 실제 기록의 `test:profile-recording`도 직접 영향 경로로 확인했다. 일반 부팅 연결은 완료했다.

설정 화면은 현재 프로필 이름/서버와 공통 설정의 적용 범위를 표시한다. 일반 전환과 활성 프로필 삭제에서 미저장 값이 있으면 저장/버리기/취소를 선택한다. 같은 프로필 확인 또는 검색/조회 필터만 변경한 경우에는 묻지 않는다. 전환 확인 중에는 입력을 잠그며 저장 중인 요청이나 HUD/알림 위치 편집이 있으면 먼저 완료하도록 안내한다. 전환을 위한 저장은 원래 프로필에 저장하고 창을 닫지 않는다.

버리기는 실제 새 ID의 config-data를 받은 때 수행한다. 뒤이은 전환 실패는 기존 ID와 초안을 유지한다. 입력/즉시 저장의 ID는 첫 비동기 조회 전에 고정하고 메인에서도 확인한다. 다른 프로필의 늦은 요청은 공통 값까지 전체 거부한다. 성공 ACK가 늦게 와도 `draft.setOwner`의 세대가 다르면 새 프로필의 초안 기준을 바꾸지 않는다. 미등록 키워드/탭은 일반 설정 수신으로 저장 승인하지 않으며 먼저 추가/입력 취소하도록 안내한다. 서버가 실제로 없을 때는 빈 필수 선택을 표시하고 임의 기본 서버를 저장하지 않는다. 프로필 관리의 서버와 같은 userServer를 사용한다.

이름/서버 변경도 설정 창에 반영하며 같은 소유자의 다른 초안은 기존 merge로 보존한다. 창을 다시 열지 않고 새 설정을 적용해 현재 탭과 검색/조회 상태를 유지한다. `check-profile-settings.ts`는 제품 HTML/preload/IPC/공유 DB로 저장·버리기·취소, 디스크/전환 실패와 재시도, 미등록 입력, 필수 서버, 저장 중/위치 편집, 늦은 요청/성공 ACK, 이름/삭제와 800×600 화면을 확인한다. 기존 설정 수신과 HUD 동작은 `test:audit`, `test:hud-edit-settings`로 함께 검사한다. 독립 설정·도구·숙제의 화면 연결은 각 계약에 구현/검증 결과를 기록했으며 일반 부팅 연결은 완료했다.

## 숙제 편집·수동 기록의 프로필 경계

프로필 모드는 현재 프로필 이름/서버와 1열의 숙제를 표시한다. 기존 캐릭터 관리 버튼은 프로필 관리를 열고 캐릭터 추가/삭제/이름/선택 IPC는 차단한다. 자동 캐릭터 후보 팝업을 열지 않으며 선택 전 실제 게임 기록은 기존 세션 대기 경로가 담당한다. 일반 모드의 다중 캐릭터 UI와 저장 형식은 유지한다.

`profileChecklistIpc`는 로컬 페이지·원래 ID·인수를 검증한다. 모든 수동 조작은 설정, 일지 완료/취소, 일 요약과 요청 ACK를 같은 DB transaction으로 저장한다. 실패는 전부 rollback하며 폼/선택은 유지한다. 로컬 요청은 `manual-checklist:<requestId>`에 enqueue/ACK를 한 번에 확정해 일반 선택 대기에 남지 않는다. 같은 요청 ID/시간/내용 재확인은 재실행하지 않고, 같은 ID의 다른 내용은 거부한다. 이 ACK는 로컬 재확인용이며 Google 전송 자료가 아니다. 완료 원문은 아래 앱 수명 계약의 30일 영수증 정리로 중복/변조 확인 증거를 유지한다.

응답 미확인 상태에서는 다시 확인을 먼저 마치도록 전환을 막는다. 다시 확인은 원래 요청을 사용하고 확인 중 다른 내용으로 편집한 폼을 지우지 않는다. 명시적 저장 실패는 같은 입력으로 재시도할 수 있다. 완료 효과음은 저장 성공 뒤 같은 프로필에서만 재생한다. 기존 내부 일지 재시도도 프로필별 키와 당시 귀속으로 실행하며 다른 프로필의 타이머와 충돌하지 않는다.

`profileChecklistTransition`은 편집 내용에 저장/버리기/취소를 제공한다. 같은 프로필 확인이나 변경 없이 편집을 열기만 한 경우에는 묻지 않는다. 버리기는 실제 새 소유자 config를 받은 후 실행하므로 뒤이은 전환 실패도 원래 초안을 남긴다. 횟수/이름 입력 팝업과 저장 중에는 먼저 완료하도록 안내한다. 새 소유자 전환도 검색/펼침 상태를 유지한다. 추가 후 다음 입력을 시작하지 않았을 때만 해당 항목으로 이동하며 검색 밖이면 안내한다. 작은 창은 편집 영역을 스크롤하고 짧은 목록에서 보조 고정 헤더를 풀어 새 항목이 가리지 않게 한다. 주간 편집의 일요일(0)도 유지한다.

검사: `test:profile-checklist`(제품 HTML/IPC/DB·오류/재확인·초안·작은 창), `test:checklist`(기존 숙제와 보류 UI), `test:window-visibility`(자동 접기), `test:audit`(기존 통계/취소/정렬), `test:profile-recording`, `test:profile-settings`, `test:companion` 및 refactor 파일. 일반 실행 연결은 완료했으며 실제 게임 실기 검증은 별도다.

## 로컬 백업의 프로필 계약

`app-data.db`와 `config.json`을 한 묶음으로 복원한다. SQLite 및 manifest 무결성, schema/완료 marker를 staging에서 확인하며 DB 없는 WAL/복구 journal이나 설정이 빠진 프로필 백업은 실제 교체 전에 거부한다. 현 PC의 `device-state.json`은 백업에서 제외하고 복원된 config의 ID를 현 PC ID로 맞춘다. DB에는 새 `restore_generation`을 남긴다. 향후 새 동기화는 이 세대를 사용하고 복원된 과거 ACK를 신뢰하지 않도록 별도로 구현해야 한다.

구형 설정만 복원하면 현재 일지는 보존한다. 기존 캐릭터→프로필 매핑을 재사용하고 백업에 없는 프로필은 삭제 표식으로 남겨 기존 일지의 소유자를 유지한다. 구형 일지만 복원하면 현재 프로필·설정을 유지하고 해당 일지 영역만 교체한다. 프로필 ID가 있는 일지는 메타데이터 없는 구형 백업으로 간주하지 않는다. 구형 캐릭터 선택 대기는 임의 프로필에 넣지 않으며 같은 원본의 대기는 중복 생성하지 않는다.

실패 후에는 DB를 먼저 다시 열고 config projection을 다시 읽는다. 설정 재로드가 DB 기본값을 JSON에 역저장하지 않도록 기기 설정만 정규화한다. 성공 안내부터 재시작까지는 쓰기·DB 재열기를 차단한다. `check-profile-backup.ts`는 실제 ZIP·SQLite·config API 및 별도 재시작 프로세스로 이 동작과 중단 journal rollback, 다른 PC의 ID 유지, 손상 DB의 부팅 실패를 확인한다. 실제 사용자 폴더의 이전은 실행하지 않았다.

## 과거 채팅 로그 복원의 프로필 경계

`ProfileService.beginHistoricalRestore`는 명시한 ID가 현재 선택과 일치하고 이름/서버 설정이 끝난 경우에만 복원을 시작한다. 시작 당시 ID/설정/게임 세션을 고정하며 작업 중 전환·삭제·프로필 설정 및 숙제 편집은 거부한다. 실제 설정 창은 대상 이름/서버와 다음 안내를 표시한다: “채팅 로그에는 접속한 캐릭터 정보가 포함되어 있지 않아 프로필을 자동으로 구분할 수 없습니다. 선택한 프로필로 모든 기록을 복원합니다.” 이름은 textContent로 표시한다.

`profileLogRestore.ts`는 로컬 DB의 `profile_log_sync_state`에 프로필별 확정 offset/집계를, `profile_log_sources`에 공통 fingerprint probe를 보관한다. `profile_log_source_ranges`의 최초 귀속 구간은 다른 프로필/미배정으로 재배정하지 않는다. 같은 파일에 뒤늦게 추가된 구간은 그때 선택한 프로필로 가져올 수 있다. 외치기는 공통이므로 다른 프로필의 날짜 재구성에서도 전체 원본을 읽는다. 기록·원본 구간·확정 위치를 한 transaction으로 commit한 다음 ACK한다. 손상 진행 정보는 빈 상태로 재분석하지 않고 거부한다.

구형 `chat-log-sync-state.json`은 변경하지 않고 기존 fingerprint와 미배정 확정 구간의 증거로만 사용한다. offset/누적 집계를 새 프로필로 복사하지 않는다. 원본 위치 없는 구형 미배정 금화/엘소/마정석 일 합계는 원래 NULL 행을 보존하고 `profile_log_legacy_aggregates`에 기준을 남겨 첫 전체 분석에서 차액만 기록한다. 이 기준이 있으면 첫 snapshot 전체가 성공하기 전에 부분 귀속을 확정하지 않는다. 네 표는 Google 변경 이력에 넣지 않으며 ZIP의 DB에 함께 포함한다.

구형 JSON 증거도 저장소 준비 때 `app_meta.legacy_chat_log_sync_state`에 한 번 보관해 다른 PC/ZIP 복원에서 현재 PC의 JSON에 의존하지 않는다. 구형 일지 영역만 교체하면 네 진행 표와 이 증거를 함께 초기화한다. 구형 설정만 복원하거나 새 DB 전체를 복원할 때는 유지한다. 최종 숙제 반영은 바깥 DB commit까지 확정 저장 경계로 감싸 실패한 메모리 설정도 복구한다.

복원 중 자동 이벤트는 대기열에 원래 세션/시각으로 저장한다. 오늘 파일의 snapshot 이후 이어받기도 완전한 물리 줄까지만 소유 구간과 대기 원본을 함께 commit한다. 성공/실패 종료 시 시작했던 세션의 대기만 재생하며 게임 종료/새 미선택 세션의 이벤트는 임의 배정하지 않는다. 저장소가 교체/폐기되면 이전 작업은 새 저장소에 반영하지 않는다. 다른 프로필의 중복 요청은 기존 작업에 합류하지 않고 거부한다.

검사: `npm run test:profile-log-restore`는 실제 UTF-8 로그/worker/SQLite/프로필 제어와 설정 HTML/preload/IPC로 입장료 음수·수익·득템·숙제 귀속, 구형 미배정/수동 기록 보존, A/B 추가 구간, 공통 외치기, 전환/삭제 차단, 확정 위치 실패 rollback·손상 거부·재시도, 실제 오늘 tail/catch-up, 게임 종료 중 원래 세션만 재생 및 800×600 경고를 확인한다. `test:profile-backup`은 네 로컬 표가 실제 ZIP/다른 PC 변환에도 보존되는지 검사한다. 기존 모드 worker/오늘 tail과 재구성은 `check-refactor-regressions.ts` 파일로 확인한다. 직접 영향 경계는 `test:profile-storage`, `test:profile-recording`, `test:profile-settings`, `test:profile-checklist`를 선택한다. 일반 부팅 연결은 완료했으며 이번 검사는 임시 폴더로만 실행했다.

## 앱 시작·종료·ZIP 복구 통합 (2026-11-04)

main은 단일 인스턴스 확인과 중단 복원 복구, preload IPC 준비 뒤 `profileApplication.startProfileApplication`을 기다린다. 기존 Google 전송을 먼저 중지하고 이전 전 스냅샷을 남긴 다음 기존 숙제를 정규화한다. 실제 저장된 서버만 이전 증거로 사용하며 자동 기본값 저장을 사용자 선택으로 보지 않는다. 신규 설치는 이름/서버를 입력하기 전의 빈 프로필 하나이고 기존 캐릭터 N개는 N개 프로필이다. 버프 정의/기록 gate를 준비한 뒤 일반 창·게임 폴링·입력을 시작한다. 준비 실패는 실행을 중단하며 기존 모드/빈 데이터로 폴백하지 않는다. 실제 사용자 폴더를 개발 검사에 사용하지 않았다.

`profileLogSource`는 파일의 고정 fingerprint와 완전한 물리/정규화 줄의 byte 구간을 파서 이벤트에 붙인다. CRLF/LF 길이는 바이너리 기준이며 재처리 ID는 원본 위치/이벤트/순서로 유지한다. 선택 전 원본은 durable 대기에 포함하고 귀속/활동/숙제/ACK를 같이 확정한다. 다른 프로필/미배정의 원본 구간과 배정 대기 구간은 과거 복원에서 제외하며 대기 구간을 현재 복원 작업이 소유하지 않는다. 날짜 전환 시 ZIP 중지는 계산한 오늘 경로 대신 실제 감시 중인 파일을 사용한다.

실행 상태는 1분·프로필 전환·백업·일반 종료·Windows 세션 종료에 저장한다. 완료 원문은 30일 뒤 최대 1,000건씩 `profile_event_receipts`로 줄여 이벤트 ID/세션/시각/해시/배정/완료 증거를 유지한다. 같은 요청은 재적용하지 않고 다른 내용의 같은 ID는 거부한다. 미배정 원문과 동기화 변경 이력은 이 정리에서 삭제하지 않는다. 강제 종료 직전 실행 상태는 마지막 checkpoint 이후 손실될 수 있으며 확정 기록/대기 원본은 DB에 남는다.

ZIP 교체는 service 작업 잠금→실제 파일 입력 drain/중지→실행 상태 checkpoint/중지→config/DB 잠금 순서다. 실패 rollback 후 DB와 config를 먼저 열고 원래 진행 및 복구 중의 게임 상태 전환을 복원한 뒤 파일 증가분을 이어받는다. 게임을 다시 시작했다면 새 세션 선택을 요구하며 기존 프로필로 자동 배정하지 않는다. 성공은 재시작까지 잠금을 유지한다. 일반 종료는 과거 worker 중단을 제한시간 안에 기다리고 마지막 checkpoint/설정 저장 후 DB 재열기와 늦은 설정 쓰기를 차단한다.

활동 프리셋의 설정 카드·검색·독 메뉴·preload/API/IPC는 제거했다. 기존 적용값과 창 배치는 유지하고 보관 원본은 이전 전 백업에 남긴다. 기존 형식 읽기/공유 창 배치의 내부 도구는 호환 검사만 유지하며 프리셋을 다시 실행하는 사용자 경로는 없다. 새 Google 동기화는 별도 개발한다.

검사: `test:profile-lifecycle`, `test:profile-log-restore`, `test:profile-recording`, `test:profile-storage`, `test:profile-backup`, `test:profile-cloud-pause`, `test:profile-settings`, `test:profiles-ui` 및 직접 변경한 보조 도구/설정 DOM 검사를 선택한다. refactor의 실제 main probe는 appData/userData 모두 임시 경로로 바꿔 실행한다. 실제 게임 플레이/설치 업데이트 검증은 남아 있다.
