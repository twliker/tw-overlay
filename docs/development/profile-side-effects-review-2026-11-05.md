# 프로필 후속 변경의 잠재 버그·부작용 검수 (2026-11-05)

프로필 순서·선택/전환·숙제 이전/복사·미배정 정리·입장료 보정·계산기 표시와 직접 연결되는 경로를 검토했다. 기존 수정 내역은 [앞선 검증](profile-diary-fixes-2026-11-05.md)에 보존한다. 이번 검수에서는 아래 문제를 추가로 수정했다.

## 발견한 문제와 조치

| 문제 | 영향 | 수정과 재현 검사 |
|---|---|---|
| 조회 범위 변경 이벤트 중복 | 사용자가 한 번 선택해도 새로고침이 두 번 실행되고 비동기 조회가 불필요하게 겹침 | 필터 값도 렌더 서명에 포함하고 변경 알림을 한곳에서만 전송. 실제 DOM 검사에서 수정 전 2회, 수정 후 1회 확인 |
| 일지 정리 결과 읽기·알림 실패 | 분류는 저장됐는데 실패로 응답하거나, 목록 갱신 실패 시 정리한 항목이 화면에 남을 수 있음 | 분류 저장과 응답 snapshot 읽기를 하나의 transaction에 포함. 저장 이후 다른 창의 알림 실패는 ACK를 취소하지 않음. 렌더러는 성공한 ID 제거를 먼저 반영하고 별도 재조회 |
| 복원/전환 중 정리 버튼 활성 | 서버는 안전하게 거부하지만 버튼이 눌려 불필요한 오류를 보임 | 처리 중에는 확인/무시 동작을 잠그고 임시로 목록이 없을 때도 완료로 안내하지 않음 |
| 입장료의 문구 금액 불일치 | 원문의 지불액 또는 새 문구가 저장 amount와 달라도 행을 중복으로 간주해 숨길 수 있음 | 원문 지불액·새 문구 금액이 각각 저장 amount와 일치하는 경우만 보정. 불완전/지원하지 않는 금액은 추정하지 않음. 수정 전 4행 중 2행만 표시되던 fixture가 수정 후 4행 모두 유지 |
| 정리 직후 메모리의 금화/엘소 조회 분류 | DB에 저장된 행은 미배정이지만 아직 저장되지 않은 금액은 이전 프로필 조회에 잠시 다시 나타남 | 저장 전 버퍼에도 동일한 분류를 적용. 수정 전 이전 프로필에 보이던 버퍼 2행이 수정 후 0행이며 미배정 합계는 저장 전후 동일. 원래 저장 귀속과 UUID는 보존 |

정리 ACK가 지연되는 사이 현재 프로필을 변경하는 경우도 추가했다. 응답 전체를 현재 상태에 덮어쓰지 않고 정리한 ID만 반영하므로 최신 프로필과 작성 중인 수동 입력/저장 대상이 유지된다.

## 검수·실행 범위

타입 검사·빌드와 관련 회귀 **17개**가 통과했다. 새 수정 뒤에는 직접 영향받는 검사만 재실행했다.

- `test:diary-profiles-ui`: 실제 HTML/preload/IPC/DB에서 단일 새로고침, snapshot 실패 rollback, 알림·목록 조회 실패, 처리 중 잠금, 현재 프로필 보호·잘못된 화면 거부, ACK 지연 중 프로필 변경과 초안 보존.
- `test:profile-diary`: 문구/금액 불일치 보존, 이전 프로필의 메모리/DB 분류 일치, 입장료 1:1·반복/다른 현재 프로필·원본/합계/내보내기·재시작, 일지 정리가 Google 변경 이력을 만들지 않음.
- `test:magic-stone`, `test:profile-log-restore`, `test:profile-recording`: 실시간/실제 과거 worker, 원본 중복 방지, 수익·지출 집계, 소유자/세션·실패 후 ACK 경계.
- `test:profile-storage`, `test:profile-backup`, `test:profile-lifecycle`: 순서·이전·격리·원자 저장, ZIP/구형 복원·재시작·중단 복구·세션 수명.
- `test:profile-homework-defaults`, `test:profiles-ui`, `test:profile-homework-progress`: 실제 배포 기본 목록·설정 복사·삭제 항목 보존·기본 복구, 프로필 정렬과 숙제 무시, 일일·주간 경계.
- `test:profile-tools`, `test:profile-stopwatch`: 실제 아티팩트 데이터와 입력/도핑, 프로필별 동시 측정·조회 범위·실패/삭제된 이력.
- `test:game-exit-reminder`, `test:profile-placement`, `test:window-visibility`: 순서에 따른 종료 안내 탭·남은 숙제·읽기 전용 동작, 좌표/DPI/작업 영역, 최소화·숨김·재표시/늦은 로딩.
- `test:profile-sync-concurrency`: 독립 프로세스 2개의 동시 전송·응답 역순·전송 중 저장·삭제 경합 등 기존 10개 시나리오와 업로드 중첩 7쌍.

재현 실패 로그 `filter-red.log`, `fee-red.log`, `buffer-red.log`와 수정 후 로그·최종 소스 해시는 `output/profile-side-effects-review/latest.json`에 연결한다. 전체/관리자 검사의 기존 결과를 이번 소스의 통과로 소급하지 않는다.

## 남은 확인과 제한

검수한 범위에서 추가 미해결 문제는 발견하지 않았다. 실제 사용자 DB는 이번 검수의 입력/수정 대상으로 사용하지 않았으며 모든 검사는 별도 임시 데이터로 수행했다.

전체 npm test, 실제 Google 계정, 실제 PC 2대·실게임, 설치 업데이트와 관리자 Z-order는 이번에 수행하지 않았다. 창의 좌표·표시 검사와 관리자 Z-order는 별개다. 요청대로 관리자 Z-order는 사용자가 실행한다. 버전은 3.3.5-beta.1이며 앞서 안내한 3.5.0 베타에서의 수동 설치 전환도 아직 미검증이다. 커밋·태그·푸시·설치 파일 생성은 하지 않았다.
