# 미배정 기록 무시와 목록 정리 (2026-11-04)

정보가 누락된 항목에 배정 불가 버튼만 남긴 것은 사용자가 정리할 수 없는 UX였다. 동작 없는 버튼을 제거하고 **무시하기**를 추가했다. 정상 과거 대기도 원하지 않으면 같은 동작으로 정리할 수 있다.

## 사용자 동작

- 무시하기를 누르면 날짜·종류·대표 내용과 대상 건수를 확인한다. 취소는 아무것도 바꾸지 않는다.
- 확인하면 해당 보관 기록을 숙제/모험일지에 반영하지 않고 대기 목록에서 제외하며 완료 안내를 표시한다. 프로필을 선택하기 전에도 가능하다.
- 저장 실패는 원본/목록을 유지해 재시도할 수 있다. 요약 조회 실패에는 **다시 확인**을 제공한다. 실제 사용 프로필/입력 초안은 유지한다.
- 현재 플레이 세션은 무시할 수 없다. 확인 중 대상 내용이 달라지면 전체 동작을 취소하고 새 요약을 확인하게 한다. 한 세션의 보관 집합 전체를 명시적 건수로 확인한다.

## 저장 계약

전용 preload/IPC에서 세션 ID와 snapshotToken을 검증하고, 서비스에서 현재 세션·전환/복원 중 요청을 거부한다. 로컬 프로필 화면만 이 동작을 호출할 수 있다. 무시에는 프로필 선택이나 자동 기록 재생이 필요하지 않다.

snapshotToken은 미배정 원본의 ID/시각/원문 전체를 순서대로 해시한 값이다. 조회의 개수/최초·마지막 시각도 일치할 때만 화면에 제공한다. 저장은 즉시 write transaction 안에서 토큰을 다시 검사한다. 같은 개수·시각의 다른 원문, 늦게 들어온 새 기록도 함께 무시하지 않는다.

무시는 payload 삭제가 아니라 **resolved_at 지정 + assigned_profile_id null**로 보관한다. 숙제/일지/Google 변경 이력에는 쓰지 않으며 다른 세션에 영향을 주지 않는다. 이미 처리된 집합의 반복 요청은 변경 없이 완료한다. 재시작과 같은 ID의 재수신에서도 대기로 다시 나타나지 않는다. 기존 정책에 따라 완료 후 30일이 지나면 원문은 압축 정리할 수 있고, 이후에도 해시 영수증으로 재수신 중복/변조를 확인한다. 스키마·클라우드 형식 변경은 없다.

검사는 소유한 임시 데이터만 사용했다. 사용자의 실제 미배정 기록을 대신 무시하거나 삭제하지 않았다. 이번에는 관련 검사만 수행했으며 전체 npm test/관리자 Z-order/실제 Google/설치 실기를 새로 통과한 것으로 표시하지 않는다. 버전·원격 브랜치·태그는 변경하지 않았고 승인 없이 푸시하지 않는다.
