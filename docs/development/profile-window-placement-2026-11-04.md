# 프로필 선택창의 게임 중앙 배치 (2026-11-04)

사용자 관리자 Z-order 통과 결과를 기록한 뒤 “프로필 선택창은 게임창 중앙에 와야 한다”는 추가 요청에 따라 수정한다. 이전 전체 자동 검사와 관리자 결과는 [통합 검수](./profile-integration-review-2026-11-04.md)의 기준 소스로 보존하고, 이번 변경은 관련 검사만 실행한다. 푸시는 명시적 승인 전까지 수행하지 않는다.

이후 추가 요청한 일일/주간 현황·진행률 바는 [프로필 숙제 현황 검증](./profile-homework-progress-2026-11-04.md)에 별도로 기록한다. 이 문서의 12개 결과는 중앙 배치 추가 당시의 소스 기준이다.

## 배치 계약

- 첫 표시 전에 최신 게임 HWND 좌표를 조회하고 `screenToDipRect(null, ...)`로 게임 모니터의 DIP 좌표를 얻는다. 첫 폴링의 캐시가 아직 없어도 바탕화면 중앙에 먼저 보였다가 이동하지 않는다.
- 프로필 선택/관리 창의 실제 크기를 기준으로 게임 중앙에 놓는다. 이전 저장/고정 위치보다 열기 시 중앙이 우선이며, 여러 모니터·음수 원점·고배율을 처리한다. 화면을 벗어날 때에는 해당 모니터 작업 영역 안으로 제한한다.
- 사용자가 직접 드래그한 뒤에는 기존 위치 정책을 사용한다. 다시 열 때는 게임 중앙으로 놓으며 기존 renderer와 작성 중인 입력은 보존한다.
- 게임 최소화/미실행/조회 실패 때는 기존 모니터 작업 영역 중앙 fallback을 사용한다. 최소화 시작 시 자동 선택창 보류 정책은 유지한다.
- 조회 중 닫힌 창이나 더 오래된 요청은 다시 표시하지 않는다. 사용자의 전체 숨김 해제는 명시적 열기 요청 시 처리하고, 이후 새로 누른 전체 숨김을 늦은 좌표 응답이 취소하지 않게 한다. 위치를 준비하는 동안 기존 위치/빈 창의 자동 표시는 보류한다.

## 검증

**타입·빌드 및 관련 검사 모두 통과. 원격 푸시 없음.** 로그와 현재 소스 fingerprint는 `output/profile-placement/latest.json`에 보관한다.

- `test:profile-placement`: 실제 windowManager resolver, 처음 폴링 전 게임 감지, 게임 위치/크기·왼쪽 200% 모니터·위쪽 모니터·부분 이탈·작은 게임, 최소화/미실행/실패/닫힘, 저장·고정 위치보다 중앙 우선 및 직접 이동 유지.
- `test:profile-windows`: 실제 main/tracker/폴링/제품 창의 12개 시작/런처/창모드 조합에서 최초 show부터 중앙인지 확인한다. 게임 따라가기 ON/OFF와 잘못된 기존 저장/고정 위치도 포함하며 시스템 메뉴 재진입과 게임 재시작을 검사한다.
- `test:window-visibility`: 조회 대기 중 전체 숨김과 늦은 응답, 다시 열기·입력 보존, 기존 창 가시성/자동 접기.
- `test:preset-position`, `test:shared-layout`: 기존 창의 최초 배치·저장·공유·늦은 로딩과 화면 이탈 복구.
- `check-refactor-regressions.ts`: 기존 창의 user-open/자동 표시/preload·ready 1회 정책과 공통 회귀. 표시 사유의 최종 변수 이름에 맞춰 정적 계약을 갱신하며 실제 동작 검사를 유지한다.

이 검사는 관리자 Z-order 재실행이나 실제 게임/Google/설치 업데이트 검증을 수행한 것으로 표시하지 않는다. 관리자 검사는 사용자 담당이며 이전 전달 결과를 보존한다.

실행 결과: `test:profile-placement`, `test:window-visibility`, `test:preset-position`, `test:shared-layout`, `check-refactor-regressions.ts`, `test:profile-windows` 통과. Windows 12개 결과 모두 `firstShowGameCentered=true`이며 실제 첫 show의 bounds를 기록해 이후 기대 좌표와 비교했다. 잘못 저장된 상대/고정 위치와 게임 따라가기 ON/OFF도 포함한다.

실행 중인 다른 테일즈위버/이전 관리자 대역 때문에 최초 앱 먼저 검사의 미실행 조건이 충족되지 않은 실패는 `windows-interference.log`로 보존했다. 실제 tracker의 창 열거·프로세스명·HWND/좌표/이벤트 경로는 유지하고 검사 프로세스의 타이틀 읽기 경계에서 소유한 게임 대역 PID만 허용해 격리했다. 사용자 게임을 닫거나 조작해 검사를 맞추지 않았다. 격리 후 12개 모두 통과했다.

일상 변경 기준에 따라 이번 배치 추가 뒤 전체 npm test를 반복하지 않았다. 이전 전체/사용자 관리자 통과 기록과 이번 관련 검사 결과를 구분한다. 사용자 지시 이후 새 커밋/태그를 푸시하지 않았다.
