# 프로필 정렬·모험일지 후속 수정 검증 (2026-11-05)

이번 작업은 프로필 순서 변경과 사용자 스크린샷에서 확인한 일지·계산기 표시 문제를 수정한다. 푸시 승인 전 로컬 후보 버전은 **3.3.5-beta.1**이다. 이전 커밋·태그는 재작성하지 않았다.

## 확정한 사용자 동작

- 프로필의 **순서 변경**에서 드래그, ↑·↓ 버튼 또는 손잡이의 방향키로 이동한다. 즉시 이 PC에 저장하며 재실행과 종료 리마인더 탭에 같은 순서를 적용한다. 선택/숙제 상태와 Google 변경 파일은 건드리지 않는다.
- 숙제 대기 기록의 **무시하기**는 기존 목록 정리 동작을 유지한다.
- 모험일지의 삭제/유실 프로필은 일반 조회 드롭다운에서 숨긴다. 기록이 있으면 **이전 프로필 정리**에서 기간·건수를 보여 주고 **무시하기 → 미배정으로 옮기기**로 정리한다. 현재 선택한 프로필로 배정하지 않는다.
- 정리한 일지는 전체 조회에 유지하고 미배정의 일·월·통계·수익·내보내기에서 함께 집계한다. 원문 행의 profile_id/UUID는 보존하고 로컬 분류만 저장해 서로 다른 캐릭터의 같은 숙제/알람이 유실되지 않게 한다.
- 조회 범위와 **새 수동 기록을 저장할 프로필**을 구분한다. 미배정 조회에서 현재 프로필 이름이 보이는 수동 입력 폼은 새 기록의 저장 대상이며 기존 조회 결과의 소유자 표시가 아니다.

## 원인과 수정

1. 삭제 프로필은 일지 보존을 위해 유지한 tombstone까지 선택지에 넣고 있었다. 일반 선택지는 현재 프로필만 사용하며 이전 소유자의 정리는 별도로 제공한다. 기록 없는 tombstone은 별도 정리 목록에도 넣지 않는다.
2. 네이티브 드롭다운의 시스템 기본 색이 어두운 화면과 맞지 않았다. 조회/수동 대상/SEED 모드에 dark color-scheme과 옵션 색을 지정했다.
3. 신고 화면의 미배정 조회 수익은 실제 NULL 소유자의 합계와 일치했다. MA담솔은 새 수동 기록의 저장 대상이었다. 실제 DB 조회/통계/수익/내보내기에 현재 소유자 자료가 섞이지 않음을 임시 fixture로 검사했다.
4. 입장료는 구형 `[자동] 입장료 5280만 Seed를 지불 하였습니다. (-5280만)`와 새 `[자동] 어벤던로드 입장료 (-52,800,000 SEED)`가 같은 날짜·초·음수 금액으로 남은 경우였다. 실시간 파서는 지불 로그 한 줄에 입장료 이벤트 하나를 낸다.
5. 구형/복원 입장료만 제한적으로 1:1 대응해 집계에서 한 번 제외한다. 같은 소유자의 쌍부터 확정한 후 삭제/유실된 소유자의 구형 기록을 대응한다. 서로 다른 현재 프로필·수동·기기/세션이 있는 구형 자료·다른 시각·같은 형식의 정상 반복은 보존한다. 원본 활동은 삭제하지 않고 모든 활동 조회/합계/내보내기가 같은 view를 사용한다. 대응 복원 원본이 제거되면 구형 원본은 다시 보인다. 원문만으로 소유자를 확정할 수 없는 과거 자료에 대한 제한된 호환 보정이며 일반 이벤트 식별 기준을 변경하지 않는다.
6. 음수 SEED는 양수 구간 조건에 들어가지 않아 원 단위 숫자로 표시됐다. 부호와 절댓값의 단위 처리를 분리하고 구형 문구의 음수 파싱도 보완했다. -1,181,900,000은 일간·주간 요약에서 -11.8억으로 표시한다.
7. 장비 데이터 생성기의 퍼센트 설명 제거 정규식이 디펜시오까지 제거했다. 11개 중복 이름을 올바른 디펜시오 이름으로 복구하고 생성기에서도 명칭을 보존했다. 능력치·이미지·목록 순서는 유지한다. 모든 프시키/아크론/이클립스 6계열의 기본/디펜시오 쌍을 실제 계산기 데이터로 검사한다.

## 실행한 관련 검사

타입 검사·빌드 및 다음 10개 회귀 검사 모두 통과했다. 전체 npm test를 반복하지 않았다.

| 검사 | 확인한 경계 |
|---|---|
| test:profile-storage | 순서 저장/재시작, 선택과 이력 무변경, 새 항목/삭제, 경합/실패 rollback |
| test:profiles-ui | 실제 preload/IPC/DOM의 드래그·버튼·키보드, 초안/선택 보존, 실패/재시도, 순서 재로드, 기존 숙제 무시 |
| test:game-exit-reminder | 사용자 순서의 프로필 탭, 마지막 사용 탭 기본 선택과 읽기 전용 동작 |
| test:profile-diary | 정리 후 모든 범위 합계, 원본/UUID·동일 숙제·알람/타이머 보존, 입장료 1:1/다른 소유자/반복/배치 복원/rollback/재시작·조회 무변경 |
| test:diary-profiles-ui | 실제 HTML/IPC/DB의 숨김·확인/취소·실패/재시도·재시작, 현재 소유자/다른 화면/잘못된 요청 거부, 드롭다운 색 |
| test:profile-tools | 실제 계산기의 모든 디펜시오 이름과 생성기 순수 함수, 기존 프로필별 입력 보존 |
| test:magic-stone | 실시간 입장료 1회 기록, 마정석 합산, 음수 부호와 실제 일간·주간 단위 표시 |

| test:profile-backup | 공유 DB 전체 ZIP·재시작·구형 자료·실패 rollback |

최종 입장료 대응 우선순위 보완 후 profile-diary, 사용자용 오류 안내 보완 후 diary-profiles-ui와 타입 검사·빌드를 재실행했다. 새 의미 변경에 영향이 없는 검사는 반복하지 않았다. 프로필 정렬과 일지 정리 확인 화면도 캡처하여 여백·가독성·버튼 배치를 확인했다.

기계 판독 결과와 로그: `output/profile-diary-fixes/latest.json`. 기존 `output/profile-review/latest.json`의 최초 전체/관리자 검사 결과는 과거 기준으로 보존하고 이번 관련 검사 결과만 후속 항목으로 연결한다.

## 남은 실기 범위

- 실제 사용자 DB는 원인 진단 목적으로 읽기 전용 조회만 수행했다. 테스트 입력이나 수정 대상으로 사용하지 않았다.
- 이번 변경 이후 전체 npm test·실계정 Google·실제 PC 2대·실게임·설치 업데이트·관리자 Z-order는 재실행하지 않았다. 관리자 창 검사는 사용자가 수행한다.
- 로컬/원격에 v3.3.5 계열 태그가 없음을 확인해 3.3.5-beta.1을 후보로 설정했다. 3.5.0 베타에서 낮은 버전으로 자동 업데이트되지 않으며 수동 설치가 필요하다. 실제 설치 전환은 미검증이다.
- 커밋·태그 생성·푸시·설치 파일 생성·Release 게시를 하지 않았다. 푸시는 별도 사용자 승인이 필요하다.
