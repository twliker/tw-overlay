# 프로젝트 전체 검수 (2026-11-05)

## 범위와 진행 상태

프로필 후속 변경에 한정하지 않고 프로젝트의 전체 npm test, 로그 부하 검사, 의존성 검사와 주요 데이터/실행 경계의 소스를 검토한다. 앱 수명/설정·백업·프로필 저장과 이전, 실시간/과거 로그, 숙제·일지·XP·버프·알림, Google 동기화, 계산기/사전/사냥 보조, 창/단축키/내장 브라우저, 외부 모니터·다운로드, 빌드/업데이트 경로를 포함한다. 모든 소스 줄을 수동으로 검토했다는 의미는 아니다.

최종 자동 검증은 완료했다. 타입 검사, 전체 npm test의 검사 50단계(별도 빌드 포함 파이프라인 51단계), 순간/지속 로그 부하 검사 2개, 강제 종료 복구·실제 3.2.2 저장 API의 이전·동기화 용량 검사 3개가 통과했다. 자동 검증 결과와 소스/로그 해시는 `output/project-review/latest.json`에 기록한다. 사용자 지시대로 관리자 Z-order, 실게임/실계정 Google, 실제 PC 2대와 설치 프로그램 검증을 자동 검사로 대체하지 않는다.

## 발견·수정한 문제

### 마지막 채팅 행에 줄바꿈이 없는 경우

`chatLogFileReader.findLastCompleteChatLogOffset`이 앞선 행의 개행을 먼저 반환해, 마지막 행이 `</br>`로 완전히 닫혔어도 snapshot에서 제외했다. 단일 행만 있는 파일은 이미 지원하고 있어 여러 행에서만 달라지는 경계였다. 오늘 로그의 마지막 입장료가 과거 복원 응답에서 빠지고 이후 이어받기로 미뤄질 수 있었다.

- 닫는 태그가 snapshot 내부에 있으면 마지막 완전한 행까지 포함한다.
- snapshot 이후에 추가된 닫는 태그나 UTF-8/HTML 작성 중인 행은 포함하지 않는다.
- 수정 전 helper 재현은 46바이트 중 24바이트만 반환했다. 실제 worker 검사도 마지막 입장료 감지 0건으로 실패했다.
- `check-refactor-regressions.ts`에 여러 행/마지막 개행 없음/고정 snapshot 경계를 추가하고, `test:profile-log-restore`에서 오늘의 닫힌 마지막 행 복원 → 나중에 추가된 개행/입장료 catch-up → 정확한 합계를 확인한다.

### 거래 서버 변경 중 늦은 응답

`tradeMonitor.forceCheck`와 UI 목록 요청은 시작 당시 서버만 참조하고 응답 때 현재 서버를 확인하지 않았다. 네냐플로 바꾼 화면에 이전 하이아칸 글이 표시될 수 있었다. 같은 서버의 두 조회가 역순으로 완료돼도 최신 목록이 덮일 수 있었다.

- 서버 세대와 UI 요청 번호를 함께 확인해 최신 요청만 반영한다. A→B→A 전환도 이전 세대의 응답을 되살리지 않는다.
- 서버 변경 시 이전 목록을 비우고, 열려 보이는 거래 창에는 새 서버 목록을 조회한다. 닫힌/숨긴 창에 불필요한 즉시 목록 요청을 추가하지 않는다.
- 기존 키워드 알림의 확인 위치·실패 재시도·중복 알림 정책은 유지한다.
- `test:audit`에 서버 전환/되돌아오기·응답 역순·열린 창 갱신 검사를 추가했다. 수정 전 별도 재현에서도 이전 서버 글이 전송됐다.

### 기본 숙제 수신 검사의 잘못된 ID 가정

전체 검사 최초 실행은 `test:profile-homework-defaults`에서 실패했다. 실제 수신 프로필/숙제가 없는 제품 회귀가 아니라, 수신 PC가 빈 기본 프로필의 로컬 ID를 재사용하는 정상 동작을 검사 코드가 고려하지 못했다. UUID 순서에 따라 송신 프로필 ID와 수신 로컬 ID가 달라질 수 있었다.

공통 remote ID → 수신 local ID 매핑으로 검사하고, 복사한 프로필 외에 수신된 모든 프로필의 이름·숙제 정의/순서·개수와 재시작 후 보존을 함께 확인하도록 보강했다. 제품의 ID/이전 정책을 검사에 맞춰 변경하지 않았다.

## 의존성 조치와 남은 위험

- `fast-uri`의 override 최소 버전을 3.1.9로 올렸다. [공식 보안 릴리즈](https://github.com/fastify/fast-uri/releases/tag/v3.1.9).
- Electron의 같은 42 계열에서 최소 버전을 42.11.16으로 올리고 잠금 파일은 42.11.18로 갱신했다. `brace-expansion`은 각 기존 주버전의 1.1.21/2.1.7/5.0.12, `undici`는 기존 6/7 계열의 6.29.1/7.30.1로 갱신했다. 강제 주버전 변경이나 electron-builder 다운그레이드는 하지 않았다.
- 잠금 파일 기준 생산 의존성 경고는 0건, 전체 의존성은 high/critical 0건·moderate 6건이다. 남은 6건은 minimatch 취약점과 연계된 빌드 도구 패키지들로 독립된 취약점 6개를 뜻하지 않는다. 앱 게임 기록/계산 경로에서 직접 사용하지 않으며 설치 파일 빌드 경로에서 사용하는 의존성이다.
- [공식 minimatch 권고](https://github.com/advisories/GHSA-g3hv-75wg-m249)의 수정 버전은 11.0.1이다. 현재 빌드 도구가 사용하는 9/10 계열에 강제 적용하면 주버전 변경이므로 별도 빌드 호환 검토가 필요하다. 이를 해결한 것으로 표시하지 않는다.
- [Electron 42.11.18 릴리즈](https://github.com/electron/electron/releases/tag/v42.11.18)는 42 계열의 지원 종료를 명시한다. 이번 수정은 알려진 패치 적용이며 장기 지원 문제를 해결하지 않는다. 지원 중인 주버전으로의 이전과 native 모듈·관리자 창 동작·패키징 검증을 후속 과제로 남긴다.

## 런타임 검증 환경

사용자가 실행해 둔 개발 앱이 `node_modules/electron/dist/resources/default_app.asar`를 사용하고 있어 npm의 교체가 EBUSY로 거부됐다. 사용자의 종료 요청에 따라 해당 개발 앱을 식별해 정상 종료/중지를 시도했지만 Windows 접근 권한으로 거부됐다. 다른 앱/게임은 종료하지 않았다.

현재 앱을 유지하면서 `output/project-review/runtime`에 잠금 파일과 같은 Electron 42.11.18을 별도 설치했다. 실제 실행 버전을 확인하고 `ELECTRON_OVERRIDE_DIST_PATH`를 전달해 같은 프로젝트의 최종 검사와 자식 프로세스를 새 런타임에서 실행한다. 새 SQLite 연결/원본 보존 smoke 검사도 통과했다. 경로/버전 검증 실패 시 검사를 시작하지 않도록 가드했다.

현재 개발 앱과 루트 node_modules의 기존 Electron 설치는 이전 버전이다. 최종 빌드/일반 개발 환경에 새 의존성 전체를 반영하려면 개발 앱 종료 뒤 `npm ci`가 필요하다. 별도 런타임 검증을 루트 node_modules 전체 갱신 완료로 표현하지 않는다.

## 배포·실기 구분

검수 중 실제 사용자 저장 데이터를 입력/수정 대상으로 사용하지 않았다. 검사별 임시 사용자 폴더와 보유한 구버전 패키지/고정 fixture를 사용한다. 원격 사용자 파일/Google 계정은 사용하지 않는다. 커밋·태그·푸시·설치 파일 생성·Release 게시는 하지 않는다. 푸시는 사용자 승인이 필요하다.

관리자 창 순서 검사는 개발 앱 종료와 `npm ci` 후, 관리자 PowerShell의 프로젝트 폴더에서 `npm run test:zorder:windows`로 사용자가 수행한다. 과거 관리자 검사 결과는 새 런타임 결과로 소급하지 않는다.
