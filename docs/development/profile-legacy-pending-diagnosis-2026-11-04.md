## 확인한 원인

- 해당 항목은 `legacy-unassigned`의 `legacy-homework` 자료 한 묶음이었다. 한 묶음 안의 수량 값이 143이며 개별 감지 로그 143개가 보존된 뜻이 아니다.
- 남아 있는 필드는 count/timestamp/sourceEventIds뿐이며 숙제 ID와 누적/절대값 적용 방식이 없었다. 이전 전 migration-source 백업에도 같은 상태여서 이번 DB 이전에서 이 필드를 잃은 것은 아니다. 더 앞선 시점에 정보가 없어진 경위는 확인하지 않았다.
- 이름 조회를 할 ID가 없어 기존 요약이 일반 이름으로 대체했고, 수량에 `회`를 붙여 완료 횟수처럼 보이게 했다. 어떤 숙제인지나 143의 적용 방식을 이 자료만으로 확정할 수 없다.
- 기존 재생은 ID 없는 값을 queuePendingHomework에 넘겼다. 이 함수는 없는 항목을 무시하므로 실제 적용 없이 ACK만 완료될 수 있었다.

`legacyHomework`가 필수 필드를 검증한다. 정상 자료는 이름과 누적 보류/절대 횟수 설정을 표시하고, 불완전 자료는 `이전 버전 숙제 1묶음`, `숙제 정보가 누락된 이전 기록 (저장 수량: 143)`처럼 안내한다. 화면 상단도 보관된 기록 수로 표현해 새 감지 수와 섞지 않는다.

배정 불가 상태를 표시하고 버튼을 막는다. 실제 재생에서도 같은 검증과 대상 숙제 존재 확인을 수행해 임의 IPC/늦은 상태에서도 무시 후 성공 처리되지 않게 한다. 배정 실패는 transaction을 되돌려 앞선 정상 처리·ACK도 보존한다. 자료를 추측해 보정하거나 자동 삭제하지 않는다.
