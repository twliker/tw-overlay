# 실시간 로그 엔진

TW-Overlay는 테일즈위버 채팅 로그 파일에 새로 추가된 줄만 추적해 알림과 일지 기능에 전달합니다.

## 처리 흐름

1. 설정된 채팅 로그 폴더와 현재 날짜 로그 파일을 확인합니다.
2. 마지막으로 처리한 위치 이후의 새 로그만 읽습니다.
3. 인코딩과 로그 형식을 검증한 뒤 채팅, 경험치, 득템, 숙제 및 버프 이벤트로 분류합니다.
4. 이벤트를 오버레이, 알림, 숙제 체크리스트와 모험 일지에 전달합니다.

플레이 프로필에서는 프로필 선택 전의 자동 기록은 보관했다가 선택 후 반영합니다. 이때 채팅 표시는 계속됩니다. 이전 세션을 수동으로 배정해도 현재 경험치·버프·현황판과 소리를 과거 상태로 바꾸지 않습니다. 앱 시작 시 프로필 선택 대기를 적용합니다.

앱이 종료되어 있던 기간의 로그는 과거 로그 동기화 기능으로 다시 분석할 수 있습니다. 기본 동기화는 아직 완료되지 않았거나 이후 내용이 추가된 파일만 이어서 처리합니다.

**이미 동기화 완료된 로그도 다시 분석하여 자동 기록 재구성**을 체크하면 보관 기간 안의 완료 파일도 처음부터 다시 읽습니다. 파일 전체 분석과 최종 상태 확인에 성공한 날짜만 기존 채팅 로그 기반 자동 모험일지·외치기 기록을 새 결과로 교체합니다. 직접 작성한 수동 일지, 메모와 알람 기록은 유지합니다. 오늘 로그는 게임이 실행 중이어도 동기화 시작 시점까지의 완전한 로그를 먼저 재구성하고, 처리 중 새로 들어온 로그를 이어서 반영한 뒤 실시간 감시로 돌아갑니다. 안전하게 이어받을 수 없는 환경이거나 과거 파일이 분석 도중 변경되면 해당 날짜의 기존 기록을 보존합니다.

과거 채팅 로그에는 어떤 캐릭터가 콘텐츠를 수행했는지 알 수 있는 정보가 없습니다. 따라서 과거 로그에서 복원한 현재 주기의 숙제 완료 횟수는 모두 **메인 캐릭터**에 반영됩니다. 지난 주기의 숙제도 리셋 주기별 완료 횟수를 계산해 실제 완료한 날짜의 모험일지에 메인 캐릭터 기록으로 복원합니다. 실시간 로그는 기존처럼 참여 캐릭터가 여러 명이면 캐릭터 선택 대기 목록을 사용합니다.

개발 중인 **플레이 프로필 모드**에서는 복원을 시작할 때 선택한 프로필에 숙제와 일지를 반영합니다. 시작 전에 대상 이름·서버와 “채팅 로그에는 접속한 캐릭터 정보가 포함되어 있지 않아 프로필을 자동으로 구분할 수 없습니다. 선택한 프로필로 모든 기록을 복원합니다.”라는 안내를 표시합니다. 이미 복원한 구간과 기존 미배정 기록은 원래 귀속을 유지하며, 이후 추가된 구간은 새로 선택한 프로필로 복원할 수 있습니다. 외치기 기록은 공통입니다.

프로필 모드의 복원 중에는 프로필 전환·삭제와 해당 설정·숙제 편집을 잠시 기다려야 합니다. 그동안 새로 감지한 자동 기록은 보관했다가 완료 후 원래 플레이 세션에 반영합니다. 저장에 실패하면 기존 기록을 보존하며 다시 시도할 수 있습니다. 이 연결은 전용 검사에서 확인한 개발 단계이며 앱 시작 시 프로필을 준비한 뒤 사용합니다.

채팅 로그 위치와 표시 필터는 앱의 **설정 → 채팅 & 로그**에서 변경할 수 있습니다.

어벤던로드 입장료 지불 로그도 과거 분석 시 음수 SEED로 복원합니다. 이미 처리한 파일까지 확실히 재구성하려면 **이미 동기화 완료된 로그도 다시 분석하여 자동 기록 재구성**을 선택합니다. 보관된 원본 로그가 없는 지출은 복원할 수 없습니다.


오늘 로그의 복원 snapshot은 마지막 행에 개행이 없어도 `</br>`로 완전히 닫혔다면 포함합니다. 작성 중인 행이나 snapshot 이후에 추가된 닫는 태그는 포함하지 않으며, 뒤이어 기록되는 개행·다음 로그는 실시간 이어받기로 처리합니다.
