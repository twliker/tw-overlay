# TW-Overlay v3.2.2 → v3.3.5 코드 리뷰

- 비교 기준은 `v3.2.2` (`ae9ce7a`)와 `8fe30e3` (`v3.3.5`)입니다. 두 커밋 사이에서 273개 파일이 변경되었습니다.
- 제품 결함 4건을 별도로 재현했습니다. 종료 안내의 표시 문제 1건과 Windows 검증 스크립트 결함 1건도 확인했습니다.

## 제품 결함

### [P1] 미배정 상태로 주기가 지난 숙제는 모험일지에 복원할 수 없음

프로필 선택 전에 이터널 플로어 완료 로그를 감지한 뒤 숙제 주기가 지나면 수동 배정에서 `이미 종료된 숙제 주기의 기록입니다`가 표시됩니다. 과거 로그 복원도 미배정 대기열에 있는 원본 줄을 건너뜁니다. `무시하기`를 누르면 해당 줄이 영구 복원 제외 대상으로 남습니다.

실제 로그 파서, 과거 로그 복원 워커, SQLite를 사용한 재현에서 대기 중과 무시한 뒤 모두 완료 일지 0건을 확인했습니다. 대기열에 들어간 적 없는 같은 형식의 완료 로그는 1건 복원됐습니다. 지난 주기 기록을 명시적으로 배정할 때 현재 체크리스트의 진행도는 유지하면서 원래 수행 날짜의 일지에 완료를 기록할 수 있어야 합니다. [숙제 배정 판정](../../src/modules/contentsChecker.ts#L1629) · [복원 제외](../../src/modules/profileLogRestore.ts#L51) · [무시 처리](../../src/modules/applicationData.ts#L860)

### [P2] 득템 저장 실패가 공허·골고다 출현 알림을 막음

프로필을 선택하면 두 출현 알림이 득템과 같은 저장 대기열에 들어갑니다. 앞선 득템 기록이 실패하면 해당 대기열 처리가 멈춥니다. 그 사이 원본 로그의 시각이 10초 유효 범위를 벗어나면 뒤늦게 처리돼도 알림이 표시되지 않습니다.

실시간 로그 감시 중 특정 득템 행의 SQLite 삽입만 실패시키고 두 출현 로그를 이어서 추가했습니다. 두 출현 이벤트가 대기열에 남았고, 알림음은 둘 다 재생되지 않았습니다. 기록을 저장할 필요가 없는 출현 알림은 원본 중복 방지와 최신성 검사를 거쳐 즉시 전달할 수 있습니다. [출현 알림 등록](../../src/modules/chatLogProcessor.ts#L520) · [대기열 순서](../../src/modules/applicationData.ts#L895) · [실패 후 재시도](../../src/modules/profileService.ts#L273)

### [P2] 앱 종료 시 미저장 고정 메모가 확인 없이 사라짐

메모 창의 닫기 버튼은 초안을 확인합니다. 앱 종료는 프로필 관리 창의 초안만 확인한 뒤 종료 플래그를 설정하며, 이 플래그가 고정 메모의 닫기 차단도 해제합니다.

실제 Electron 고정 메모 창에서 미저장 상태를 만든 뒤 제품의 종료 확인 및 창 닫기 경로를 실행했습니다. 확인창 없이 메모 창이 닫혔고 저장값은 이전 상태였습니다. 앱 종료 확인에 고정 메모도 포함해야 합니다. [앱 종료 경로](../../src/main.ts#L365) · [닫기 차단 해제](../../src/modules/windowManager.ts#L1213) · [메모 초안 보호](../../src/pinned-note.html#L89)

### [P3] 거래 게시판 새로고침이 자신이 시작한 목록 조회 때문에 취소됨

수동 새로고침이 키워드 검색을 기다리는 동안, 그 검색에서 시작한 목록 조회가 요청 번호를 올립니다. 내부 목록 조회가 실패해도 처음 수동 요청은 이미 무효가 되어 자체 목록 조회를 건너뜁니다. 화면은 기존 목록을 보여 준 채 로딩을 종료할 수 있습니다.

첫 목록 조회만 실패하고 두 번째 조회부터 성공하도록 만든 테스트에서 실제 목록 요청은 한 번으로 끝났고 목록 갱신 이벤트도 전달되지 않았습니다. 수동 새로고침 한 번이 목록 조회 결과까지 처리하도록 요청 흐름을 합치는 편이 좋습니다. [키워드 검색 후 목록 조회](../../src/modules/tradeMonitor.ts#L311) · [수동 새로고침](../../src/modules/tradeMonitor.ts#L442)

### [P3] 종료 안내 탭에 서버명이 표시되지 않아 동명 프로필 구분이 어려움

실제 종료 안내 화면에서 이름이 같은 프로필 탭이 나란히 표시되는 것을 확인했습니다. 탭 본문에는 이름과 남은 숙제 수만 표시됩니다. 서버명은 툴팁과 접근성 이름, 선택한 탭 아래에 있습니다. 이름과 숙제 수가 같을 때는 탭 자체에도 서버명을 표시하면 선택 전에 대상을 구분할 수 있습니다. [종료 안내 탭 렌더링](../../src/renderer/game-exit-reminder.ts#L61)

## Windows 검증 스크립트 결함

`npm run test:profile-windows`는 원본 상태에서 `An object could not be cloned` 오류로 실패했습니다. 테스트가 `executeJavaScript`에서 함수 대입식의 결과인 함수 객체를 반환하기 때문입니다. 임시 테스트 복사본에서 반환값만 `undefined`로 바꾼 뒤 앱 선실행, 게임 선실행, 최소화 상태에서 시작하는 경우를 사이드바·독과 창모드·테두리 없는 창모드로 조합한 12개 시나리오가 모두 통과했습니다. [실패한 테스트 코드](../../scripts/check-profile-windows.ts#L286)
