# 프로필과 Google 동기화 시점 설계안

2026-11-04 후속 구현은 [Google 계약](./google-drive-sync-contract.md)을 따른다. 아래의 중지/향후 표현은 로컬 프로필 개발 단계의 기록이며, 새 동기화 개발 승인 이후에도 옛 형식의 전송은 계속 중지한다.

## 동기화 범위 확정

이번 작업 단위의 Google 동기화 대상은 프로필·숙제·휴대 가능한 환경설정이다. 모험일지의 수익·지출·득템·보스·수동 기록은 로컬 DB에만 저장하고 업로드/다운로드하지 않는다. 같은 프로필을 두 PC에서 사용해도 모험일지는 각 PC에 별도로 남으며 원격 합산하지 않는다. 아래 과거 검토 중 모험일지 전송·PC 간 합산 예시는 향후 확장 가능성에 대한 참고이며 이번 구현·검증 범위에서 제외한다. 로컬 profile_id와 고유 기록 ID의 필요성은 원격 전송 여부와 별개다.



상태: 사용자와 합의한 동기화 기본 정책. 간격·전송 예산·세부 프로토콜은 구현 시 측정/검증한다. 향후 Google 동기화 구현을 지금 활성화하지 않으며 기존 동기화 코드는 재사용 전제가 아니다.

## 목적과 경계

프로필 선택/전환·로컬 기록의 완료와 원격 동기화의 완료를 분리한다. Google 연결이 없어도 프로필 생성·설정 변경·숙제·일지 기록은 완료된다. UI에 “저장됨”과 “동기화 완료”를 혼동하여 표시하지 않는다.

## 활동 상태 판정

- 활동: 게임 클라이언트가 실행 중이고 최소화/숨김 상태가 아닌 경우. 다른 프로그램으로 포커스를 옮긴 것만으로 휴식 상태로 판단하지 않는다.
- 휴식: 게임 창이 최소화·숨김 상태이거나 게임이 종료된 경우. 오버레이만 숨긴 상태와 게임 창 자체가 숨겨진 상태를 구분한다.
- 일시적인 창모드 전환/탐지 오류로 상태가 흔들리지 않도록 안정된 상태 변화만 수용한다. 숨김은 같은 세션의 일시 중단이고 종료는 세션 종료다.
- 휴식 중에도 채팅 파일 감시·파싱과 의미 있는 활동의 로컬 저장은 유지한다. 일반/외치기/시스템 채팅 수신 자체는 동기화 요청의 근거가 아니다. 파서가 확정한 득템·수익·지출·숙제 등과 단순 채팅 수집을 구분한다.

## 다운로드 시점

| 계기 | 동작 | 사용자 대기 |
|---|---|---|
| 앱 시작, 이미 연결된 Google 계정 있음 | 프로필 목록·삭제 표식·변경 지표 및 필요한 변경을 백그라운드 확인 | 로컬 데이터가 있으면 기다리지 않음 |
| 게임 신규 실행 또는 게임 실행 중 앱 시작 | 선택창은 로컬 목록으로 즉시 표시. 최신 확인은 병행하되 이미 진행 중이면 합침 | 프로필 선택 전 자동 기록만 기존 정책대로 대기 |
| 프로필 선택/전환 | 로컬 프로필을 원자 적용한 후 대상 변경 확인을 우선 예약. 방금 성공적으로 확인한 상태면 불필요한 재조회 생략 | 기존 로컬 프로필은 원격 응답을 기다리지 않음 |
| 게임 창이 보이는 활동 상태 | 30초 간격으로 작은 변경 지표 확인, 변경 있을 때 필요한 본문만 수신 | 없음 |
| 게임 최소화·숨김·종료 | 5분마다 작은 변경 지표를 확인하고 변경이 있을 때만 필요한 데이터 수신 | 없음 |
| 숨김/최소화에서 복귀 | 최신 변경을 즉시 한 번 확인하고 30초 활동 주기로 변경. 같은 세션의 프로필은 유지 | 없음 |
| 휴식 중 프로필 관리·일지 조회·설정 편집을 사용자가 시작 | 필요한 데이터의 최신 확인을 한 번 예약. 화면 로컬 조작과 초안 보존 | 없음 |
| 네트워크 복구 | 최신 변경 확인과 미전송 처리를 한 사이클로 합쳐 예약하고 활동/휴식 주기를 재개 | 없음 |
| 사용자가 “지금 동기화” 실행 | 확인·병합·전송 사이클을 즉시 예약하고 결과 표시 | 동기화 작업 상태만 표시, 플레이 입력은 유지 |

- 앱 시작 확인은 게임이 꺼져 있어도 최초 한 번 수행할 수 있지만 이후에는 게임 표시 상태에 따라 활동 30초/휴식 5분 주기로 확인한다.
- 휴식 중에도 다른 PC의 변경은 5분 주기 또는 복귀/화면 열기/수동 동기화 때 확인한다. 휴식 중 즉시 반영을 보장하지 않는다.
- 간격은 최초 구현의 조정 가능한 정책값이다. 실제 Google 프로젝트 quota·사용량·실측 결과에 따라 조절하되 UI/프로필 저장 구조를 바꾸지 않도록 한 곳에서 관리한다.
- 프로필마다 별도 주기 타이머를 만들지 않는다. 앱 단위 스케줄러 하나가 작업을 합치고 선택 프로필의 데이터에 우선순위를 준다.
- 같은 계기의 중복 요청은 진행 중인 작업에 합치고, 성공 조회 캐시와 지터로 시작 시/주기 호출 폭주를 막는다.
- 원격 목록 수신 시 화면 정렬/선택/스크롤을 갑자기 바꾸지 않는다. 사용자가 조작한 뒤에는 현재 선택을 유지하고 신규 항목만 알린다.

## 업로드 시점

| 계기 | 동작 |
|---|---|
| 숙제·프로필 정보·동기화 대상 환경설정 저장 | 로컬 원본과 변경 이력을 즉시 commit. 마지막 변경 후 3초에 묶음 업로드 예약 |
| 연속 변경 | debounce를 연장하되 첫 미전송 변경부터 최대 10초에 전송 시도 |
| 활동 중 자동 숙제 변경 | 개별 API 호출 대신 다른 숙제 변경과 묶어서 전송. 모험일지 기록은 로컬에만 저장 |
| 휴식 중 일반/외치기/시스템 채팅 수신 | 동기화 예약 없음. 채팅 수집 자체를 원격 변경으로 취급하지 않음 |
| 휴식 중 실제 숙제 자동 감지 | 로컬에 즉시 저장. 마지막 숙제 변경 후 30초, 첫 변경부터 최대 60초에 묶음 전송 시도. 미배정 기록은 귀속 전 전송하지 않음 |
| 득템·수익/지출·수동 기록 등 모험일지 변경 | 로컬 저장만 수행. 전송 예약 없음 |
| 휴식 중 사용자가 숙제·프로필·동기화 대상 설정을 직접 수정 | 사용자 조작은 활동 중과 같이 3초/최대 10초 정책을 적용 |
| 프로필 전환 | 이전 프로필의 미전송 변경을 즉시 전송 예약. 새 프로필 적용은 로컬 저장 성공 이후 진행하며 네트워크를 기다리지 않음 |
| 게임 최소화·숨김 진입 | 확정된 미전송 변경이 있을 때만 즉시 한 사이클 전송 예약. 이후 정기 확인은 5분 주기로 변경 |
| 게임 종료 | 확정된 미전송 변경이 있을 때만 즉시 한 사이클 전송 예약. 세션 종료 후 미배정 기록은 자동 배정/업로드하지 않음 |
| 앱 종료 | 내구성 있는 변경 이력을 먼저 확정하고 최대 3초간 전송 완료를 시도. 남으면 다음 실행에서 이어서 처리 |
| 오프라인/오류 | 로컬 변경은 보존. 재시도는 지수 지연+지터와 상한을 적용. 오류마다 즉시 무한 재시도하지 않음 |

- 3초/10초 및 휴식 중 자동 기록의 30초/60초는 전송 시작을 시도하는 정책이며 서버 반영 완료 시간 보장이 아니다. 대기열·오프라인·호출 예산·서버 지연으로 실제 완료는 늦어질 수 있다.
- 저장 직후 앱이 강제 종료되어도 종료 이벤트에 의존하지 않고 outbox에서 복구한다.
- 전송 작업은 특정 profileId/변경 ID 집합을 캡처한다. 전송 중 다른 프로필로 바뀌어도 대상으로 삼은 ID를 변경하지 않는다.
- 창 위치·크기·현재 선택 프로필·로그 경로 등 기기 전용 변경은 Google 전송을 예약하지 않는다.
- 새로 생성한 프로필의 필수 이름·서버가 확정되기 전 초안은 전송하지 않는다. 삭제는 일지 원본 삭제가 아니라 프로필 삭제 표식을 전송하는 기존 보존 정책을 따른다.

## 원격 수신·충돌 적용 규칙

- 업로드는 무조건 로컬 전체를 덮어쓰는 요청이 아니다. 기준 revision 이후 원격 변경을 확인하고 병합·조건부 저장한다. 상세 프로토콜은 새 동기화 구현 시 검증한다.
- 수신 결과로 현재 플레이 프로필을 자동 전환하지 않는다. 활성 프로필은 PC별 로컬 상태다.
- 숙제 등 확정 데이터는 로컬 미전송 변경을 포함해 병합하고 목록/일지를 갱신한다. 늦게 도착한 원격 snapshot을 새 로컬 변경 위에 그대로 덮어쓰지 않는다.
- 환경설정 편집 중에는 사용자 초안과 편집 대상 profileId를 유지한다. 충돌한 항목은 보류/안내하고 입력을 버리지 않는다.
- 현재 플레이 중인 프로필의 원격 삭제나 프로필 이름/서버 변경은 조용히 적용하지 않는다. 기록 귀속을 유지하고 사용자에게 확인할 상태로 전환한다. 잘못된 프로필로 기록을 이어가거나 다른 프로필로 임의 전환하지 않는다.
- 다른 프로필에 대한 응답은 해당 프로필 원본에만 적용하며 현재 화면의 프로필을 바꾸지 않는다.

## 첫 연결/다른 PC 최초 복원 예외

- 사용자 확정: 처음 연결할 때 로컬과 원격 데이터가 모두 있으면 자동 덮어쓰기하지 않고 가져오기·병합·로컬 유지 범위를 안내해 선택을 받는다. 자동 생성된 빈 기본 프로필이 원격 프로필 수를 하나 늘리지 않도록 연결 절차에서 매핑한다.
- 선택하려는 프로필이 원격에만 있고 아직 로컬 데이터가 없다면 해당 프로필의 최초 다운로드가 끝나야 선택을 완료한다. 로딩·오류·재시도를 표시하고 그동안 발생한 기록은 대기시킨다.
- 로컬 원본이 이미 있는 일반 사용/프로필 전환과 이 최초 다운로드 예외를 구분한다.
- 오래된 원격 데이터/기존 동기화 형식을 새 구조에 자동 수용하지 않는다. 최초 연결/이전 정책은 새 프로토콜의 별도 검증 대상이다.

## 현재 프로필 개발이 제공할 계약

1. 단일 저장 계층: local commit 후에만 성공 반환. 저장과 변경 이력은 함께 확정.
2. 모든 명령·기록·비동기 응답은 profileId를 명시하고 변경되지 않는 기록/operation ID를 사용.
3. 프로필 목록 갱신과 활성 프로필 전환은 서로 다른 작업/API.
4. 미배정 기록은 세션별 내구 저장, 선택 후 명시적 귀속. 종료된 이전 세션은 별도 배정.
5. 기기 설정과 휴대 가능한 프로필/공통 설정을 분리하고 후자만 변경 알림을 생성.
6. 저장 상태/원격 전송 상태를 분리하여 표시할 수 있는 상태 모델.
7. 로컬 전용 버전에서는 Google 작업은 모두 비활성. 같은 계약을 사용하는 스케줄러를 향후 추가.

## 검증 항목

- 업로드 대기·전송 중·오프라인에도 프로필 선택/전환과 숙제 저장이 가능.
- 연속 변경 묶음, 최대 대기, 중복 다운로드 병합, 기기 전용 변경에 전송 없음.
- 시작 순서 2종·최초 복원·원격 데이터만 있는 프로필 선택.
- 전환/이름·서버 변경/삭제 중 늦은 응답, 편집 초안 보존.
- 앱 강제 종료·게임 종료·네트워크 복귀 후 누락/중복 없음.
- 활동 중 30초/휴식 중 5분 확인, 전환 시 한 번 flush, 의미 없는 채팅 수신으로 추가 호출 없음.
- 휴식 중 실제 활동 로그 및 직접 편집은 저장·전송되며 숨김 복귀 시 같은 프로필 유지.
- 활동 주기·휴식 중 의미 있는 변경·재시도·전송량을 합산한 프로젝트 단위 호출 예산 검증.

## 두 PC 이상 동시 실행 (사용자 요구 반영)

- 초기 정책은 게임 창 표시 시 30초, 최소화·숨김·미실행 시 5분 확인으로 한다. 10분 주기로의 조정은 이후 실제 사용량/지연 측정에 따라 판단하며, 현재 설계에서는 5분 고정으로 단순화한다.
- 다른 PC의 활성 여부를 알아내기 위해 별도 고빈도 heartbeat를 추가하지 않는다. 각 PC가 자기 게임 창 상태에 따라 확인 주기를 정한다.
- PC A에서 프로필 X, PC B에서 프로필 Y를 선택할 수 있다. 원격 최신 활성 프로필로 자동 수렴하지 않으며 어느 PC의 선택도 다른 PC를 전환시키지 않는다.
- 동시 플레이는 서로 다른 프로필뿐 아니라 서로 다른 게임 계정을 하나의 프로필로 선택하는 경우도 지원한다. 게임의 같은 계정 중복 접속 제한을 앱 프로필의 단일 기기 사용 보장으로 해석하지 않는다. 데이터 종류별로 동시 기록/편집을 처리하며 동일 프로필 양쪽 숙제 횟수를 무조건 합산하지 않는다.
- 휴식 중인 PC가 오래된 값으로 숙제/설정을 수정하더라도 저장은 즉시 완료한다. 업로드 전에 원격 변경을 확인하여 미전송 operation과 병합한다. 오래된 프로필 전체 snapshot으로 원격을 덮어쓰지 않는다.
- PC B가 숨김에서 복귀하면 5분 타이머를 기다리지 않고 최신 확인을 우선한다. 로컬 데이터가 있으면 플레이는 계속 가능하나 확인 중/충돌 상태를 별도로 표시하고 편집 초안은 유지한다.
- 서로 다른 설정 필드 수정은 함께 보존한다. 같은 필드의 상충 변경은 기준 revision으로 판정하고 해결 불가능하면 사용자에게 충돌을 알린다. 기기 시각만으로 최신을 정하지 않는다.
- 숙제는 프로필 단위로 격리하며 횟수 감소·해제·N/A·초기화를 손실 없이 표현한다. 같은 캐릭터의 PC 이동 시 이전 PC의 늦은 업로드가 새 진행도를 덮지 못하도록 기준 revision 및 고유 변경 ID를 확인한다. 게임이 꺼진 PC에서 같은 프로필을 수동 편집하는 예외는 가능하므로 불명확한 상충은 보류/안내하고 무조건 합산하지 않는다.
- 일지 기록은 고유 기록/원본 이벤트 ID로 중복 방지한다. 같은 과거 로그를 두 PC가 복원해도 중복되지 않아야 한다.
- 프로필/숙제 삭제 표식은 다른 PC의 오래된 데이터로 항목이 부활하지 않도록 유지한다. 현재 사용 중인 프로필의 원격 삭제는 사용자 조작 흐름과 기록 귀속을 보존하며 안내한다.
- 한 사용자 두 PC뿐 아니라 전체 사용자의 동시 실행 PC 수를 기준으로 quota 예산을 산정한다. 타이머에는 지터를 두고 네트워크 오류 시 재시도 상한을 공유한다.

### 동시 PC 필수 시나리오

1. A 활동/B 휴식 상태에서 A의 숙제 변경을 B가 주기 확인 및 즉시 복귀 확인으로 수신.
2. A 프로필 X/B 프로필 Y 동시 기록, 서로의 선택 프로필 유지.
3. 서로 다른 프로필의 숙제·환경설정 동시 변경 격리. 같은 프로필을 다른 PC로 옮길 때 늦은 업로드/재전송으로 횟수 감소·해제·N/A·초기화가 되돌아가지 않음.
4. B 오프라인 중 수정 후 A가 더 수정/삭제한 상태에서 B가 복귀: 덮어쓰기·부활·중복 없음.
5. 두 PC의 같은 원본 과거 로그 복원, 전송 ACK 유실 후 재시도: 기록 한 번 반영.
6. 휴식 PC의 직접 편집은 3초/최대 10초 전송, 자동 의미 있는 기록은 30초/최대 60초 전송. 일반 채팅 수신만으로 확인 타이머가 앞당겨지지 않음.

## 같은 프로필의 두 PC 플레이 (사용자 지적 반영)

- 게임 계정과 앱 프로필은 강제 일대일 연동 관계가 아니다. 숙제를 사용하지 않는 사용자가 서로 다른 계정을 두 PC에서 플레이하면서 하나의 앱 프로필로 기록을 모을 수 있다. 같은 프로필의 두 PC 사용을 차단하거나 원격 활성 상태로 다른 PC를 전환하지 않는다.
- 프로필의 이름은 자유로운 표시 이름이고 서버는 기존 userServer다. 실제 캐릭터 이름은 입력받지 않으며 프로필 이름으로 에타를 조회하지 않는다. 채팅로그 실제 닉네임의 에타 조회에 서버를 사용한다. 별도 공유 모드를 강제로 만들거나 게임 계정 인증을 요구하지 않는다.
- 모든 기록/변경에는 profileId뿐 아니라 deviceId, sessionId, 고유 recordId/changeId 및 기기별 순번을 저장한다. 수신/재전송 중 같은 ID는 한 번만 반영한다.
- 모험일지의 독립된 활동 기록은 합집합으로 병합한다. PC A +100, PC B +200은 전체 +300이며 어느 한 PC의 총액으로 대체하지 않는다. 합계는 병합된 원본 기록에서 계산한다.
- 두 PC의 같은 시각·같은 내용·같은 금액이라는 이유만으로 기록을 하나로 축약하지 않는다. 독립된 두 플레이 이벤트와 동일 이벤트의 재전송을 구분한다. 과거 동일 원본 파일의 재분석은 별도 source identity/발생 위치를 이용해 중복 방지하며, 이 identity의 생성·복원·복사 파일 정책은 프로토콜 설계에서 검증한다.
- 수동 기록은 저장 대상 profileId를 명시하고 각각 독립 recordId를 부여한다. 수신자가 현재 프로필이나 현지 시각으로 귀속을 재해석하지 않는다.
- 환경설정의 서로 다른 필드 변경은 함께 보존한다. 같은 필드의 동시 상충은 기준 revision/인과 정보를 통해 감지하고 양쪽 값을 보존한 채 해결한다. 최신 PC 시각만으로 무조건 삭제하지 않는다.
- 숙제 사용 여부와 일지 동시 기록 가능 여부는 별개다. 숙제를 사용하지 않으면 해당 쓰기가 발생하지 않을 뿐, 동시 일지 병합은 동일하게 지원한다. 숙제를 사용하는 같은 프로필의 상충하는 진행도/해제/N/A/리셋은 무조건 합산하거나 최댓값을 취하지 않고 데이터 의미에 맞게 해결해야 한다. 정확한 캐릭터별 숙제 관리에는 별도 프로필을 사용한다.
- 경험치·버프·어벤던로드의 진행 중 세션 상태와 HUD는 기기/세션별로 관리한다. 다른 PC에서 받은 세션이 현재 PC의 타이머를 리셋하거나 HUD 상태를 대체하지 않는다. 확정된 일지 기록만 해당 프로필에 합산한다.
- 사용자에게 추가 계정 설정을 요구하지 않는다. 필요 시 일지 상세에서 기록 출처(기기/세션)를 확인할 수 있게 하고, 충돌 안내는 실제 상충에만 표시한다.

### 최소 동시 기록 검증

1. 같은 프로필 PC A/B에서 독립 수익·지출·득템·수동 기록 발생 → 누락 없이 합산.
2. 같은 changeId/recordId 재전송·ACK 유실·재시작 → 중복 없음.
3. 같은 시각·문구·금액인 독립 두 이벤트 → 두 기록 유지.
4. 같은 과거 원본 로그의 두 PC 복원과 한 파일 내 반복 문구 → 재분석 중복 방지와 정당한 반복 이벤트 보존.
5. 프로필 공통 설정의 다른 필드 병합/같은 필드 충돌 보존, 현재 기기 세션/HUD 격리.
6. 같은 프로필을 쓰는 두 PC의 숙제 상충과 프로필 삭제/기록 편집 경합을 별도로 검증.

기본 메타데이터 후보는 profileId, deviceId, sessionId, 고유 recordId/changeId, 기기별 순번, 기준 revision/확인한 변경 범위 및 표시용 시각이다. 필드별 버전 벡터가 필요한지 또는 더 단순한 기준 revision 방식으로 충분한지는 이 동시 사용 시나리오를 검증해 확정하며, 게임 접속 제한을 근거로 검증을 생략하지 않는다.

## 이력 정리와 최초 연결의 확정 정책

반영 완료된 변경 이력은 안전한 기준 snapshot에 통합해 자동 정리하되 미전송·미해결·삭제 및 중복 방지에 필요한 정보를 보존한다. 장기 미접속 PC의 변경 유실/삭제 항목 부활을 검증한다. 최초 Google 연결의 가져오기/병합 범위는 사용자에게 안내하며 자동 덮어쓰기하지 않는다. 상세는 profile-storage-design.md 결정 ④ 및 ⑦을 따른다.
