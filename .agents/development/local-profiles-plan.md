# 로컬 플레이 프로필 개발 명세

상태: 로컬 프로필 기능 구현 및 자동 검증 완료. 당시 `test:profiles:acceptance` 26개 단계와 소스/패키지 각각12개 Windows 조합의 증거를 보관했다. 이후 Google 재개발은 `google-drive-sync-contract.md`와 별도 관련 검증을 따른다. 실제 게임·관리자·설치는 배포 확인이며 개발 검사에는 임시 폴더만 사용한다.

저장 방식은 config.json(기기 전용) + app-data.db(프로필·숙제·설정·로컬 일지 등)의 혼합 구조로 확정했습니다. 기존 DB 백업·확장·검증 후 이전 절차는 [profile-storage-design.md](./profile-storage-design.md)를 따릅니다. PC별 동기화 파일, 인터넷 보정 시간과 예외 충돌 처리, 안전한 변경 이력 자동 정리 원칙도 확정했으며 구체적 프로토콜과 성능은 구현 때 검증합니다.

## 확정 요구사항

- 프로필 하나는 캐릭터 하나에 대응한다. 한 프로필에 여러 캐릭터를 등록하는 구조를 사용하지 않는다.
- 프로필별로 해당 캐릭터의 숙제 전체를 관리한다. 모험일지는 단일 DB를 유지하며 기록 테이블에 profile_id를 추가해 기록 주체를 식별한다. 전체/프로필별 조회를 지원한다.
- 숙제 범위에는 해당 캐릭터의 숙제 정의·커스텀 숙제, 완료 횟수·완료 시각, N/A를 포함한다.
- 프로필 전환이 캐릭터 전환이다. 프로필 내부의 별도 캐릭터 선택 및 자동 숙제의 캐릭터 선택 대기는 새 UX에서 필요하지 않다. 프로필 선택 전 기록 대기는 유지한다.
- 게임 클라이언트가 새로 실행되면 프로필 선택창을 표시한다.
- 게임이 이미 실행 중인 상태에서 TW-Overlay를 시작해도 프로필 선택창을 표시한다.
- 프로필 선택 전 자동 기록은 대기시키고, 선택이 확정되면 선택한 프로필에 순서대로 반영한다.
- 사이드바와 독의 시스템 메뉴에서 프로필 기능에 접근한다.
- Google 동기화와 신규 프로필의 연동은 보류한다. 로컬 기능이 안정화된 뒤 기존 동기화 개선과 함께 진행한다.

## 저장 경계

- 프로필: 사용자가 정한 표시 이름·서버와 해당 프로필의 숙제 데이터 전체. 실제 캐릭터 이름은 입력받지 않는다.
- 모험일지: 단일 DB에 저장하고 기록별 profile_id로 구분한다. 프로필 전환으로 DB 파일을 교체하지 않는다.
- 공통 유지 제안: 창 배치·크기, 단축키, 음량, 게임/채팅 로그 경로와 PC 환경 설정.
- 활동 프리셋 기능은 완전히 제거한다. 프로필 기능으로 명칭만 바꾸거나 화면 배치용으로 남기지 않는다. 현재 적용된 실제 설정값은 유지한다.
- 업데이트 시 기존 캐릭터 수와 이전 후 프로필 수를 일치시킨다. 비어 있는 기본 프로필은 기존 캐릭터 하나의 정보와 숙제 상태로 채워 재사용하고, 나머지 캐릭터만 새 프로필로 만든다. 기본 프로필을 별도로 남겨 캐릭터 수보다 프로필이 하나 많아지면 안 된다. 공통 숙제 정의는 각 프로필에 복사하되 완료 상태에는 해당 캐릭터의 상태만 반영한다. 원본은 이전 성공 확인 전까지 보존한다.
- 기존 모험일지는 복제하지 않는다. 캐릭터 귀속을 확정할 수 없는 기록은 profile_id 미지정으로 보존한다.
- 모험일지 외의 SQLite 테이블과 로그 복원 상태는 사용처를 조사하여 프로필 귀속 여부를 구현 전에 명시한다. 과거 로그 복원 fingerprint/offset을 다른 프로필에서 무조건 재사용하거나 과거 기록을 임의 프로필로 자동 복제하지 않는다.

## 세션 진입과 선택 대기

- 새 게임 세션 감지와 앱 시작 당시 실행 중인 게임 감지를 하나의 멱등 진입 함수로 연결한다.
- 최소화·복귀, 좌표 변경, 반복 폴링만으로 선택창을 중복 생성하거나 재표시하지 않는다.
- 선택 전에는 마지막 사용 프로필에 자동 기록을 쓰지 않는다. 자동 숙제, 수익·지출·득템과 후속 일지 집계의 쓰기 경로를 모두 조사한다.
- 선택 전 대기 이벤트에는 원래 날짜·시각과 세션 식별자를 보존한다. 재시도·선택창 재개방·앱 재시작에도 유실과 중복 반영이 없도록 내구성 있는 대기 저장 및 처리 완료 표시를 설계한다.
- 선택창을 닫은 경우에도 기록을 임의 프로필에 반영하지 않으며 시스템 메뉴에서 다시 선택할 수 있어야 한다.
- 프로필 선택창은 게임 입력을 막는 전체 화면 모달로 만들지 않는다. 현재 선택 또는 선택 대기 상태를 사용자가 확인할 수 있게 한다.

## 전환 및 동기화 격리

- 전환 시 진행 중인 DB 쓰기·자동 숙제 처리·과거 로그 복원과 경합하지 않도록 전환을 직렬 처리한다.
- 이전 프로필에서 시작된 비동기 결과가 새 프로필에 기록되지 않도록 프로필 ID/전환 세대를 확인한다.
- 새 프로필 로드 실패 시 현재 프로필과 데이터를 보존하고 성공으로 표시하지 않는다.
- 기존 Google 동기화의 시작 시 pull, 주기 작업, 설정 저장 hook 및 이미 진행 중인 응답이 프로필 데이터를 덮어쓰거나 업로드하지 못하도록 격리한다. Google 연결 자격을 임의로 삭제하지 않는다.
- 로컬 백업·복원에는 프로필 데이터와 선택 대기를 포함한다. 설정 공유가 프로필 데이터를 의도치 않게 이동시키지 않는지 확인한다.

## 관련 검증 계획

전체 테스트를 매 작업 실행하지 않고 단계별 관련 검사만 선택한다.

1. 저장/마이그레이션: 기존 데이터 보존, 프로필별 숙제 격리·단일 일지의 귀속 및 합산 조회, 재시작, 실패 롤백.
2. 세션 진입: 앱 → 게임, 게임 → 앱 두 순서, 반복 감지·최소화 복귀 시 중복 선택창 방지.
3. 자동 기록: 선택 전 대기, 원래 시각 보존, 선택 후 한 번 반영, 전환 중 늦은 응답 격리.
4. 실제 UI: 시스템 메뉴 진입, 선택·관리, 현재 프로필 표시, 입력/포커스 보존.
5. 동기화 격리: 예약·진행 중인 Google 작업이 로컬 프로필을 변경하지 않음.
6. 과거 복원/백업: 프로필 소유권, offset 분리, 중복 방지, 기존 백업 호환성.

코드 변경 시 typecheck 및 새 프로필 전용 회귀 검사를 우선한다. 기존 소비 경로를 변경할 때만 해당 기능 검사를 추가한다.

## 2026-11-02 설계 보완

- 빈 기본 프로필에 매핑할 캐릭터는 기존 선택 캐릭터를 우선하는 방안을 권장한다. 이미 사용자 데이터가 있는 프로필은 빈 기본 프로필로 취급하거나 덮어쓰지 않는다. 기존 캐릭터가 2개면 최종 프로필도 2개이며, 기본 프로필 + 복사본 2개로 총 3개를 생성하지 않는다.
- 캐릭터 ID → 프로필 ID의 영구 대응표를 저장하여 이름 변경·재실행·중단 후 재시도에도 같은 프로필을 재사용한다.
- 숙제 복사 대상: 항목 ID, 이름, 카테고리, 표시 여부, 커스텀 여부, 자동 감지 설정, 초기화 규칙, 최대 횟수 및 해당 캐릭터의 완료 여부·횟수·N/A·완료 시각. 초기화 판정은 복사 완료 후 기존 규칙으로 수행한다.
- 기존 미배정 숙제 대기는 특정 캐릭터에 임의 반영하지 않고 별도 미배정 상태로 보존하는 방안을 권장한다.
- 기록 테이블의 profile_id는 표시 이름 대신 변경되지 않는 식별자를 사용한다. 캐릭터 귀속이 없는 과거 기록은 NULL로 유지하고 전체 및 미지정 조회에 포함하는 방안을 권장한다.
- 날짜별 diaries 집계는 현재 날짜 단일 키이므로 profile_id 열 추가만으로 프로필별 통계가 완성되지 않는다. 일/주/월 통계·숙제 분모·활동 점수·내보내기의 필터 기준과 집계 키를 함께 설계한다. 전체 집계 중복 계산을 방지한다.
- 프로필 간 같은 숙제/시각이 있을 수 있으므로 중복 제거 키·삭제 조건·과거 로그 재구성 범위에도 귀속을 반영한다. 하나의 원본 로그를 프로필마다 중복 복제하지 않는다.
- 자동 기록의 프로필 ID는 이벤트 발생/수신 시점에 확정하여 전환 후 늦은 저장이 다른 프로필에 귀속되지 않게 한다. 선택 전 대기는 선택 확정 시 귀속한다.
- 앱 공통 로그·메타데이터 테이블은 목적을 확인해 공통으로 유지한다. 프로필 귀속을 갖는 기록 테이블과 공통 테이블의 상세 목록은 구현 전 확정한다.

## 최초 설치와 기존 사용자 구분

- 완전 신규 설치로 기존 캐릭터·프로필 데이터가 없으면 빈 기본 프로필을 정확히 1개 생성한다.
- 기존 캐릭터가 있는 업데이트 사용자는 빈 기본 프로필을 기존 캐릭터 하나로 채워 재사용하고 나머지만 생성한다. 기존 캐릭터가 N개면 최종 프로필은 N개다.
- 이미 프로필이 있는 사용자는 앱 시작마다 빈 기본 프로필을 추가하지 않는다. 초기화·이전 중단 후 재시도에도 기본 프로필이 중복 생성되지 않아야 한다.
- 빈 기본 프로필은 사용자 지정 이름·진행도·일지 기록이 없는 시작 상태이며, 기본 제공 숙제 목록은 사용할 수 있다.

## 추가 합의 — 조회·삭제·복원·동기화

- 프로필은 자유롭게 정하는 프로필 이름과 서버를 포함하며 서버 선택은 필수다. 실제 캐릭터 이름을 요구하거나 프로필 이름으로 추정하지 않는다. 서버를 추측하거나 “나중에 설정”으로 건너뛰게 하지 않는다. 기존 캐릭터 이전 시 서버가 없으면 필수 선택 단계에서 입력받아야 한다.
- 모험일지는 최초 기본 조회를 전체로 제공하며 전체/현재 프로필/프로필 미지정 조회를 지원한다.
- 프로필 삭제 시 프로필 및 해당 숙제는 삭제하되 모험일지 기록은 보존하고 삭제된 프로필로 식별한다. 프로필 식별자를 재사용하지 않는다.
- 과거 로그 복원은 복원 시작 시 선택된 프로필로 모든 대상 기록을 가져온다. 실행 전에 대상 프로필 이름·서버와 함께 다음 안내를 표시한다: “채팅 로그에는 접속한 캐릭터 정보가 포함되어 있지 않아 프로필을 자동으로 구분할 수 없습니다. 선택한 프로필로 모든 기록을 복원합니다.”
- 복원 대상 프로필은 시작 시 고정한다. 처리 중 프로필 전환이 있더라도 대상이 바뀌지 않아야 한다. 기존 기록 재구성·중복 제거와 재배정 정책은 별도 상세 설계가 필요하다.
- 초기 프로필 버전에서는 기존 Google 동기화 전체를 일시 중지하고 연결 자격은 보존한다. 실행 중인 응답·업로드 예약도 프로필 데이터를 변경하지 못하게 한다.
- 수동 기록은 저장할 프로필을 표시하고 사용자가 변경할 수 있도록 확정했다. 현재 선택 프로필을 기본값으로 사용하되 일지 조회 필터와 구분하며, 저장 요청 시 대상 프로필을 고정한다. 현재 수동 쓰기 경로는 모험일지 득템/SEED 수익·지출 입력, 마정석 계산기 일지 저장, 보스 알림 화면/사이드바의 보스 기록이다. 자동 로그 기록에는 이 선택 UI를 적용하지 않는다.

## 프로필별 환경설정 설계

### 확정된 수동 기록

모험일지 득템·SEED 수익/지출, 마정석 계산 결과, 보스 수동 기록에 저장 대상 프로필을 표시하고 변경할 수 있게 한다. 조회 중인 프로필과 현재 플레이 프로필을 혼동하지 않게 한다. 프로필 미선택 시 임의로 마지막 프로필에 저장하지 않는다.

### 분리 원칙

캐릭터 플레이 방식에 따라 달라지는 값은 프로필별로 저장하고, PC 환경·화면 배치·조작·계정 연결은 공통 유지한다. 사용자에게 설정마다 상속 모드를 고르게 하는 방식은 초기 버전에 도입하지 않는다. 아래 분류를 확정 기준으로 설계한다. 활동 프리셋은 완전히 제거하며 별도 우선순위를 두지 않는다.

### 서버와 연동되는 값

- 프로필 서버는 기존 환경설정의 “주 사용 캐릭터 서버”인 userServer와 동일한 값이다. 프로필 전용의 별도 서버 설정을 신설하거나 서로 다른 값으로 중복 저장하지 않는다. userServer의 기존 코드값을 그대로 사용한다.
- userServer를 프로필별 설정으로 소유하고, 환경설정 서버 선택 UI와 프로필 생성/편집 UI는 같은 저장값을 읽고 변경한다. 프로필 전환 시 기존 userServer 소비 경로에도 선택 프로필의 값을 일관되게 적용한다.
- 에타 조회·캐릭터 식별·서버별 닉네임 메모 등 기존 userServer 소비 기능은 동일한 값을 참조한다. 매직위버 거래 모니터링의 별도 항목 tradeServer는 이번 캐릭터 서버와 혼동하거나 임의로 통합하지 않는다.
- 서버별 닉네임 메모/시세/조회 캐시는 서버 키로 공통 관리할 수 있으며 같은 서버의 다른 프로필에 무조건 복제하지 않는다.
- 서버 선택은 신규 생성·기존 캐릭터 이전 모두 필수다. 서버 없는 초안은 보존할 수 있으나 프로필 사용/선택 완료로 처리하지 않는다. 기본 빈 프로필 1개 생성 요구는 유지하며 사용 전 설정 단계에서 서버를 반드시 지정한다.
- 에타 자동 조회는 채팅로그에 등장하는 실제 닉네임을 선택 프로필의 userServer로 조회하는 기존 기능을 말한다. 프로필 이름으로 에타를 조회하지 않으며 프로필 생성/수정 화면에는 캐릭터 이름 입력이나 에타 조회 UI를 추가하지 않는다. 서버 선택 필수 여부와 채팅 에타 조회 성공 여부는 구분한다.

### 변경·전환 UX

- 프로필 설정에는 대상 프로필 이름/서버와 “이 프로필에 적용”, 공통 설정에는 “모든 프로필에 적용”을 표시한다.
- 설정 편집 중에는 대상 프로필을 고정한다. 다른 창에서 전환되더라도 기존 초안을 새 프로필에 저장하지 않는다. 미저장 입력이 있으면 저장/버리기/전환 취소를 선택하게 한다.
- 새 프로필은 기본값 또는 기존 프로필의 환경설정만 복사하는 방식으로 생성할 수 있다. 환경설정 복사에는 숙제 진행도·일지·실행 중 타이머를 포함하지 않는다. 기본 설정으로 시작하며 “다른 프로필의 환경설정 복사”를 선택할 수 있도록 한다.
- 기존 캐릭터 이전 시 앱 기본값으로 초기화하지 않는다. 사용자가 현재 저장해 둔 실제 설정값 중 프로필별 항목을 각 캐릭터 프로필에 그대로 복사한다. 누락된 항목만 기존 앱의 기본값 해석 규칙을 따른다. 공통 항목은 기존 저장값을 공통으로 유지한다. 복사 후에는 각 프로필이 독립적으로 변경되며, 마이그레이션 재실행으로 사용자가 변경한 프로필 값을 덮어쓰지 않는다.
- 활동 프리셋의 생성·목록·적용·수정·삭제 UI, 메뉴·IPC·preload API, 저장/공유/백업의 활성 기능 경로를 제거한다. 다른 기능과 공유하는 창 배치·설정 적용 기능은 유지한다. 현재 적용된 사용자 설정을 초기화하지 않고, 구버전 백업의 프리셋 필드가 기능을 되살리지 않도록 호환 처리를 한다. 사용자 문서·기능 계약 인덱스·관련 검사도 함께 갱신한다.
- 실행 중인 경험치·어벤던로드 집계와 버프 타이머는 환경설정과 구분한다. 프로필 전환 시 다른 캐릭터의 실행 상태가 이어지지 않도록 수명/귀속을 설계한다.

## 최종 합의 — 기록 경계와 사용자 경험

- 새 프로필은 기본 설정으로 시작하되 다른 프로필의 환경설정만 복사할 수 있다. 숙제 진행도·모험일지·실행 중 타이머는 복사하지 않는다. 기존 사용자 업데이트의 실제 사용자 설정값 복사와 신규 생성의 기본값을 구분한다.
- 프로필 선택 없이 게임이 종료되면 해당 세션의 대기 기록을 미배정으로 보존한다. 다음 세션에서 선택한 프로필에 자동 배정하지 않는다. 사용자가 별도로 배정할 수 있게 한다.
- 프로필 전환 시 경험치·어벤던로드 집계와 버프 타이머는 다른 캐릭터로 이어지지 않게 구분한다. 전환만으로 진행 중인 기록을 버리지 않고 원래 프로필에 보존한다.
- 같은 과거 원본 로그를 다른 프로필로 복원해도 중복 기록을 생성하지 않는다. 이미 다른 프로필에 귀속된 기록의 재배정은 변경될 범위·대상 프로필을 별도로 안내한 후 명시적으로 실행한다.
- 프로필 이름·서버가 변경돼도 내부 ID는 유지하고 과거 기록의 연결을 보존한다. 표시 이름 변경으로 에타를 조회하지 않는다. 서버 변경 시 실제 닉네임 조회는 새 서버 키를 사용하며 늦은 이전 서버 응답이 새 정보를 덮지 못하게 한다.
- 선택창은 최근 사용 프로필부터 보여주고 키보드 탐색 및 Enter 선택을 지원한다. 서버 설정이 완료된 프로필만 선택 완료할 수 있다.
- 숙제창 및 수동 기록 저장 화면에는 현재 대상 프로필 이름과 서버를 항상 표시한다. 일지 조회 필터, 현재 플레이 프로필, 저장 대상 프로필은 각각의 역할을 구분한다.
- 프로필 전환 중 중복 클릭을 막고 진행 상태를 표시한다. 전환 실패 시 기존 프로필·입력·기록을 유지하고 재시도 가능하게 한다.
- 미저장 설정 편집 중 전환에는 저장/버리기/취소 선택을 제공하고, 아무 입력도 없을 때 불필요한 확인창을 띄우지 않는다.

### 추가 관련 검증

- 신규 기본 빈 프로필 생성 후 필수 서버 설정, 기존 캐릭터별 서버 필수 선택, “나중에 설정” 우회 불가.
- 임의 프로필 이름의 생성/수정/사용, 프로필 이름으로 에타를 조회하지 않음, 채팅 실제 닉네임 조회에서 서버 변경 중 늦은 응답 격리.
- 활동 프리셋 기능 제거 후 기존 사용자 실제 설정 유지, 구버전 백업/공유 파일로 기능이 부활하지 않음.
- 최근 사용 정렬·키보드/Enter 선택·대상 프로필 표시·전환 중 중복 클릭·실패 시 기존 상태 보존.
- 세션 종료 후 미배정 기록 보존 및 다음 세션 자동 배정 방지, 과거 복원 중복 방지·명시적 재배정.

### 서버 설정 이전 규칙 보완

- 기존 환경설정 userServer에 사용자가 저장한 유효한 값이 있으면 다른 환경설정과 마찬가지로 이전 대상 프로필에 복사한다. 이미 선택된 유효값이 있으므로 빈 값으로 되돌리거나 불필요하게 재선택을 강제하지 않는다.
- 실제로 서버 값이 없거나 유효하지 않은 경우에만 필수 서버 선택 단계를 제공한다. 임의 기본 서버를 새로 선택한 것처럼 저장하지 않는다.
- 서버 설정의 단일 원본과 화면 간 일치, 프로필 전환 후 기존 에타 조회 경로 반영을 관련 회귀 검사에 포함한다.

## Google 동기화 재개발 전제 (사용자 확정)

향후 Google 동기화는 기존 구현 전체를 설계 근거/재사용 전제로 삼지 않고 새로 개발한다. 기존 코드·원격 파일·상태 파일·operation 형식과 맞추기 위해 프로필 저장 구조를 왜곡하지 않는다. 현재 필요한 기존 동기화 정지 처리는 임시 격리 조치이며 새 동기화 아키텍처의 기반이 아니다. 기존 사용자 데이터 보존·이전 요구와 기존 동기화 구현 호환 요구는 구분한다.

## 동기화 시점 검토

프로필 구현에 필요한 로컬 저장/전환과 향후 동기화의 관계는 [profile-sync-lifecycle.md](./profile-sync-lifecycle.md)의 사용자 검토안으로 정리했다. 현재 Google 동기화를 활성화하지 않으며 주기 숫자는 최초 제안값이다.

## 두 PC 동시 사용 전제

프로필 하나의 기본 의미는 캐릭터 하나지만 게임 계정과 강제 연결하지 않는다. 사용자는 서로 다른 계정을 두 PC에서 하나의 프로필로 선택해 숙제 없이 일지를 모을 수도 있다. 이를 차단하지 않고 모든 기록에 프로필·기기·세션·고유 기록 ID를 부여하여 독립 이벤트를 합산하고 재전송은 중복 제거한다. 같은 프로필의 환경설정·숙제 상충은 추가 기록의 병합과 분리해 처리한다. 게임 접속 제한을 같은 앱 프로필의 단일 작성자 보장으로 사용하지 않는다.

## 모험일지 동기화 범위 정정

모험일지 단일 DB 및 profile_id는 로컬 기록 구분을 위한 확정 요구다. 모험일지 Google 동기화는 이번 범위에서 제외하기로 확정했다. 과거 다중 PC 일지 합산/전송 예시는 이번 구현에 적용하지 않는다.

## 이번 동기화 범위 최종 확정

사용자 확정: 현재 작업 단위에서는 모험일지를 동기화하지 않는다. 프로필·숙제·휴대 가능한 환경설정만 향후 새 Google 동기화의 대상이다. 모험일지는 단일 로컬 DB에서 profile_id로 전체/프로필별 조회하며 각 PC의 기록은 각 PC에만 남는다. 로컬 백업·복원은 모험일지를 포함하되 Google 동기화와 별개다. 이전의 모험일지 동기화 예시는 이번 요구에서 제외한다.

## 동기화 파일 단위 확정

Google 동기화 재개발은 PC별 변경 파일 방식을 사용한다. 각 PC는 자기 파일에만 쓰고 다른 PC의 변경을 프로필 ID/공통 scope별로 읽어 반영한다. 로컬 일지는 전송하지 않는다. 상세는 profile-storage-design.md의 결정 ②를 따른다. 동일 항목 상충은 버전/인터넷 보정 시간으로 순서를 확정할 수 없는 예외에만 양쪽 값을 보존해 사용자 선택을 받는다.

## 변경 시각 기준 확정

변경 시각은 인터넷 시간으로 앱 내부 시간을 보정해 UTC로 저장한다. 실제 변경 시각과 업로드 시각은 구분한다. 저장마다 시간 서버를 호출하거나 Windows 시계를 바꾸지 않으며 오프라인에도 로컬 저장은 계속한다. 시간 불확실성이 남고 버전으로도 순서를 확정할 수 없는 상충은 양쪽 값을 보존하여 사용자 선택을 받는다. 상세는 profile-storage-design.md 결정 ③-A를 따른다.

## 예외 충돌 처리 확정

동일 항목의 서로 다른 변경이 버전 및 인터넷 보정 시간으로도 순서를 확정할 수 없을 때에만 양쪽 값을 보존하고 사용자 선택을 받는다. 인터넷 연결 실패만으로 확인창을 띄우지 않는다. 미해결 충돌은 비차단 상태 표시로 알리고 다른 작업은 계속한다.

## 남은 사용자 선택 완료

- 변경 이력은 안전한 현재 상태로 통합하여 자동 정리한다. 미전송·미해결 변경 및 필요한 삭제/중복 방지 정보는 보존한다.
- 마지막 프로필 삭제를 허용하고 새 ID의 빈 기본 프로필 하나를 생성한다. 일지는 삭제된 프로필의 기록으로 보존한다.
- 자유롭게 정한 프로필 이름과 서버가 유효하면 프로필을 사용할 수 있다. 프로필 이름으로 에타를 조회하지 않는다. 필수 서버는 채팅로그 실제 닉네임의 기존 에타 조회에 사용한다.
- 향후 Google 최초 연결 시 로컬·원격에 모두 데이터가 있으면 자동 덮어쓰기하지 않고 가져오기/병합 범위를 사용자에게 안내한다.
- 상세 기준과 검증은 profile-storage-design.md 결정 ④~⑦을 따른다. 내부 테이블·API·파일명·임계값 등은 이 사용자 정책 안에서 설계하고 검증한다. Google 동기화 활성화는 현재 로컬 프로필 구현과 분리한다.
